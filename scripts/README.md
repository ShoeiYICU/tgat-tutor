# scripts — เครื่องมือตรวจข้อมูล

ใช้ไลบรารีมาตรฐานของ Python เท่านั้น **ไม่ต้องติดตั้งอะไรเพิ่ม** (ต้องมี Python 3.9 ขึ้นไป)

สเปคที่สคริปต์เหล่านี้ยึด อยู่ในโฟลเดอร์ [`../spec/`](../spec/)

---

## คำสั่งที่ใช้บ่อย

```bash
python scripts/validate.py
```
ตรวจฟอร์แมตทุกไฟล์ใน `data/` — นี่คือ **ชั้นที่ 1** ของระบบตรวจใน `spec/07-quality-and-legal.md`

```bash
python scripts/render_template.py --stress
```
รันโจทย์แม่แบบทุกข้อ สุ่มค่าข้อละ 200 ครั้ง เพื่อหากรณีที่โจทย์พัง — **ชั้นที่ 2** และเป็นขั้นที่ข้ามไม่ได้

```bash
python scripts/render_template.py --show math.trig.sine_law -n 10
```
ดูโจทย์ที่สุ่มได้จริง 10 ข้อ ใช้ตรวจด้วยตาว่าโจทย์อ่านรู้เรื่องและตัวเลือกดูน่าเชื่อ

```bash
python scripts/selftest.py
```
ทดสอบว่า validator ยังจับข้อผิดพลาดได้ครบ (รันหลังแก้ `validate.py` หรือ `speclib.py`)

---

## ทำอะไรได้บ้าง

| ไฟล์ | หน้าที่ |
|---|---|
| `speclib.py` | ส่วนกลาง: อ่าน JSON, ตรวจนิพจน์ให้ปลอดภัย, คำนวณนิพจน์, แปลง `difficulty_signals` เป็นช่วงความยาก |
| `validate.py` | ตรวจ 4 ชนิดข้อมูล: ผังหัวข้อ / บทเรียน / โจทย์ / ข้อสอบจริง |
| `render_template.py` | สุ่มโจทย์จากแม่แบบ + ตรวจว่าแม่แบบไม่พัง |
| `selftest.py` | ทดสอบตัว validator เอง (19 ประเภทข้อผิดพลาด) |

### `validate.py` ตรวจอะไร

- JSON อ่านได้ ฟิลด์บังคับครบ ค่า enum ถูกต้อง
- `topic_id` ทุกตัวมีอยู่จริงในผังหัวข้อ / `id` ไม่ซ้ำกันทั้งโปรเจกต์
- `requires` ไม่มีวงวน (ผังต้องเป็น DAG) และไม่ชี้ไปหาหัวข้อที่ไม่มี
- MCQ มี `is_answer: true` ตัวเดียว / `distractor_reasons` ครบทุกตัวเลือกที่ผิด
- `hints` ครบ 3 ระดับ / `solution_steps` ทุกขั้นมี `why_md`
- `difficulty` สอดคล้องกับ `difficulty_signals` ตามตาราง C.3
- นิพจน์ใน `template` ปลอดภัย (ห้ามเรียกฟังก์ชันนอกรายการที่อนุญาต) และใช้แต่ตัวแปรที่ประกาศไว้
- ข้อสอบจริง: `visibility` สอดคล้องกับ `license_status` / `checked` ต้องมีที่มาให้ย้อนตรวจ /
  `stem_md` เป็น null ต้องมี `notes` (กันการเดาเนื้อโจทย์)

### `render_template.py --stress` ตรวจอะไร

สุ่มค่าจาก `vars` ตาม `constraints` แล้วเช็คทุกรอบว่า

- คำนวณ `answer_expr` ได้ ไม่หารศูนย์ ไม่รากติดลบ ไม่ได้ NaN
- ตัวเลือกลวงไม่มีตัวใดเท่ากับคำตอบ และไม่ซ้ำกันเอง
- ตัวเลือกลวงไม่ห่างจากคำตอบเกิน 5 เท่า และไม่ติดลบ (ไม่งั้นเดาได้ว่าผิด)
- ผ่าน `quality_exprs` ที่แม่แบบเขียนไว้ (ถ้ามี)
- `constraints` ไม่แน่นเกินไปจนสุ่มโจทย์ไม่ออก

**ระดับผลลัพธ์:** `ต้องแก้` = โจทย์ใช้ไม่ได้ ต้องแก้ `constraints` / `ควรดู` = ใช้ได้แต่คุณภาพต่ำ

## ใช้ตอนไหน

```
ได้ไฟล์ JSON จาก GPT
   ↓
python scripts/validate.py                  ← ต้องผ่านก่อน
   ↓
python scripts/render_template.py --stress  ← ต้องผ่านก่อน
   ↓
ให้ AI ต่างค่ายตรวจเนื้อหาและเฉลย (spec/05, spec/06)
   ↓
คนตรวจตามตารางใน spec/07 ส่วน "ชั้น 4"
   ↓
เปลี่ยน review_status เป็น human_verified
```

สองขั้นแรกฟรีและเร็ว จับข้อผิดพลาดที่คนมองด้วยตาไม่เห็น **รันทุกครั้งก่อนเสียเวลาคนตรวจ**

## ข้อจำกัดที่ต้องรู้

สคริปต์พวกนี้ตรวจได้แค่ **ฟอร์แมตและความสอดคล้องภายใน** ตรวจ **ไม่ได้** ว่า

- เนื้อหาบทเรียนถูกต้องทางวิชาการหรือไม่
- เฉลยของโจทย์ที่ไม่มี template ถูกหรือผิด
- ปี พ.ศ. ชื่อบุคคล มาตรากฎหมาย ถูกหรือไม่
- ข้อสอบที่อ้างว่าเป็นของจริง เป็นของจริงหรือ AI แต่งขึ้น

สี่ข้อนี้ต้องใช้คนหรือ AI ตัวที่สอง ดู `spec/07-quality-and-legal.md` และ `spec/09-real-exam-papers.md`
