# 06 — Prompt สำเร็จรูป: แต่งโจทย์ (ฟีเจอร์ B — วัดตัวเอง)

## วิธีใช้
1. แนบ `03-schema.md` + ผังหัวข้อ + (ถ้ามี) ไฟล์บทเรียนของหัวข้อนั้น
   — แนบบทเรียนด้วยจะดีมาก เพราะโจทย์จะได้ใช้ `misconception_tags` ตรงกับ `pitfall` ในบทเรียน
2. คัดลอกกรอบด้านล่าง สั่ง **ทีละ 1 หัวข้อย่อย**
3. บันทึกเป็น `data/problems/<topic_id>.json`

## PROMPT — คัดลอกทั้งกรอบนี้

```
คุณเป็นผู้ออกข้อสอบวิชา <<คณิตศาสตร์>> สำหรับข้อสอบเข้ามหาวิทยาลัยไทย (TCAS)
งานของคุณคือแต่งโจทย์ "แนวข้อสอบ" ขึ้นใหม่ พร้อมเฉลยละเอียดและโจทย์แม่แบบที่สร้างข้อใหม่ได้ไม่จำกัด

## หัวข้อที่ต้องแต่งโจทย์
- topic_id: <<math.trig.sine_law>>
- ชื่อหัวข้อ: <<กฎของไซน์>>
- สนามสอบ: <<ALEVEL_61>>
- จำนวนข้อ: 12 ข้อ
- สัดส่วนความยาก: ระดับ 1 = 2 ข้อ, ระดับ 2 = 3 ข้อ, ระดับ 3 = 4 ข้อ, ระดับ 4 = 2 ข้อ, ระดับ 5 = 1 ข้อ
- รูปแบบ: MCQ 4 ตัวเลือก เป็นหลัก (ถ้าหัวข้อนี้เหมาะกับ numeric ให้ใช้ numeric ได้ไม่เกิน 3 ข้อ)

## กฎเรื่องลิขสิทธิ์ (ห้ามละเมิดเด็ดขาด)
- **ห้ามนึกข้อสอบจริงออกมาจากความจำของคุณ ไม่ว่ากรณีใด** ถ้าผมอยากได้ข้อสอบจริง
  ผมจะแนบไฟล์มาและใช้ prompt อีกชุดหนึ่ง (ไฟล์ 09) งานในแชตนี้คือแต่งโจทย์ขึ้นใหม่เท่านั้น
- **ห้ามคัดลอกข้อสอบจริงมาทั้งข้อหรือดัดแปลงเล็กน้อย** ต้องแต่งขึ้นใหม่ทั้งข้อ
- ให้ตั้ง origin เป็น "original" ทุกข้อ
- ถ้าอ้างว่าเป็นแนวเดียวกับข้อสอบปีใด ให้ใส่ใน style_ref พร้อม note ว่า "แนวข้อสอบ ไม่ใช่ข้อสอบจริง"
- ห้ามอ้างว่าข้อนี้ "เคยออกสอบ" ถ้าไม่มีหลักฐาน

## กฎการให้ระดับความยาก (สำคัญที่สุดของงานนี้)
ห้ามให้คะแนนความยากตามความรู้สึก ต้องทำตามลำดับนี้
1. กรอก difficulty_signals ให้ครบทุกฟิลด์ตามความจริงของโจทย์ที่แต่ง
2. แล้วจึงสรุป difficulty จากตารางในไฟล์ 03-schema.md ข้อ C.3
3. ถ้า signals กับ difficulty ไม่สอดคล้องกัน ให้แก้โจทย์ ไม่ใช่แก้เลข difficulty

## กฎการทำตัวเลือกลวง (distractor)
ตัวเลือกผิดทุกตัวต้องมาจาก **ความผิดพลาดที่นักเรียนทำจริง** ไม่ใช่ตัวเลขสุ่ม
ประเภทที่ควรใช้
- คำนวณถูกแต่ใช้สูตรผิด / ใช้สูตรที่ใกล้เคียงกัน
- ลืมแปลงหน่วย หรือแปลงหน่วยผิดทาง
- สลับตัวเศษกับตัวส่วน / สลับตัวแปร
- เครื่องหมายผิด (บวกเป็นลบ)
- ตอบค่ากลางทางที่ยังไม่ใช่คำตอบสุดท้าย (ทำถูกแต่หยุดก่อน)
- ตีความโจทย์ผิดในจุดที่คนพลาดบ่อย
ห้ามใช้ตัวเลือกลวงที่ "ดูผิดชัดเจน" เช่น ค่าติดลบในโจทย์หาความยาว หรือค่าที่ต่างจากคำตอบ 100 เท่า
ต้องกรอก distractor_reasons ทุกตัวเลือกที่ผิด และ misconception_tags

## กฎการทำโจทย์แม่แบบ (template)
นี่คือฟีเจอร์หลักของเว็บ ต้องทำให้ครบทุกข้อที่ทำได้
- vars ต้องมีช่วงค่าที่กว้างพอจะสุ่มได้หลากหลาย แต่ไม่กว้างจนโจทย์ไม่สมจริง
- constraints ต้องกันกรณีที่โจทย์พัง เช่น มุมรวมเกิน 180 องศา รากติดลบ ส่วนเป็นศูนย์
- answer_expr ต้องเป็นนิพจน์ Python บรรทัดเดียวที่คำนวณคำตอบได้จริง
  ใช้ได้เฉพาะฟังก์ชันในรายการที่อนุญาตในไฟล์ 03-schema.md ข้อ C.4
- distractors ต้องเป็นนิพจน์ที่สะท้อนความผิดพลาดจริงเช่นกัน ไม่ใช่ "answer * 2"
- quality_rules ต้องระบุเงื่อนไขที่ทำให้โจทย์ที่สุ่มออกมาใช้ได้ (ช่วงคำตอบ ตัวเลือกไม่ซ้ำ ฯลฯ)
- ถ้าหัวข้อนี้ทำ template ไม่ได้จริง ๆ ให้ใส่ template เป็น null และอธิบายเหตุผลใน template_note

### ทุก template ต้องมีเฉลยของตัวเอง (ฟิลด์บังคับ)

โจทย์ที่สุ่มใหม่มีตัวเลขไม่เหมือนข้อต้นฉบับ ถ้าใช้เฉลยเดิมจะผิด
จึงต้องทำเฉลยแบบแทนค่าได้ **สามฟิลด์นี้ขาดไม่ได้**

| ฟิลด์ | กฎ |
|---|---|
| `steps_tpl` | อาร์เรย์ อย่างน้อย 2 ขั้น ทุกขั้นมี `do_md` และ `why_md` ที่ไม่ว่าง |
| `hints_tpl` | 3 ระดับเสมอ |
| `explanation_tpl` | ข้อความเดียว ไม่ว่าง |

เขียนแทนค่าด้วย `{ชื่อตัวแปร}` ได้เหมือน `stem_tpl` และใช้ `{answer}` ได้ด้วย
ถ้าเฉลยต้องอ้างค่ากลางทาง **ห้ามเขียนเลขตายตัว** ให้ประกาศเพิ่มใน `display` เช่น
`"display": {"nm1": "n - 1", "prod": "(n - 1)*d"}` แล้วเขียน `${nm1} \times {d}={prod}$`

**กฎเหล็ก: คำใบ้ห้ามมีค่าคำตอบอยู่ในข้อความ**
จุดที่พลาดง่ายคือค่าอื่นในคำใบ้ไปตรงกับคำตอบโดยบังเอิญ เช่นข้อที่ตอบ `k+1`
แต่คำใบ้พิมพ์ `a1` ออกมา — ถ้าสุ่มได้ `a1 = k+1` ก็กลายเป็นเฉลย
กรณีนี้ให้เพิ่ม `constraints` เช่น `"a1 != k + 1"` **ไม่ใช่ลบตัวเลขออกจากคำใบ้**

รายละเอียดทั้งหมดอยู่ใน `03-schema.md` ข้อ C.7

**ข้อสำคัญ: คุณต้องตรวจ template ด้วยตัวเองก่อนตอบ**
เลือกค่ากลางช่วงของทุกตัวแปร แทนค่าใน answer_expr คำนวณด้วยมือ
แล้วเทียบกับคำตอบใน choices ของโจทย์ต้นแบบ ต้องได้ค่าเท่ากัน
ถ้าไม่เท่า แปลว่า answer_expr ผิด ให้แก้ก่อนตอบ

## กฎการทำคำใบ้ (hints) — ต้องมี 3 ระดับทุกข้อ
- ระดับ 1: ชี้ว่าเรื่องนี้เกี่ยวกับอะไร ยังไม่บอกสูตร
- ระดับ 2: บอกสูตรหรือแนวทางที่ต้องใช้
- ระดับ 3: ทำขั้นแรกให้ดู แต่ **ยังไม่เฉลยคำตอบ**

## ข้อห้ามอื่น
- ห้ามให้คำตอบอยู่ตำแหน่งเดิมทุกข้อ ให้กระจายตำแหน่ง
- ห้ามใช้ตัวเลือกแบบ "ถูกทุกข้อ" หรือ "ไม่มีข้อถูก" เกิน 1 ข้อในชุด 12 ข้อ
- ห้ามแต่งโจทย์ที่ต้องรู้เนื้อหาเกินขอบเขตหัวข้อนี้ ยกเว้นข้อระดับ 4-5 ที่จงใจผสมหัวข้อ
  (กรณีนั้นต้องใส่หัวข้อที่ผสมลงใน topic_ids ให้ครบ)
- ห้ามใส่ข้อความอธิบายนอก JSON
- review_status ต้องเป็น "ai_draft" ทุกข้อ

## รูปแบบคำตอบ
JSON ตาม 03-schema.md ส่วน C.1 เท่านั้น
ถ้าตอบ 12 ข้อในรอบเดียวจะยาวเกิน ให้แบ่งเป็น 3 รอบ รอบละ 4 ข้อ
ขึ้นต้นแต่ละรอบว่า "ข้อ N ถึง M" แล้วตอบเฉพาะอาร์เรย์ problems ของรอบนั้น
ผมจะพิมพ์ว่า "ต่อ" เพื่อขอรอบถัดไป

## ก่อนตอบทุกรอบ ให้ตรวจตัวเองตามรายการในภาคผนวกของ 03-schema.md ให้ครบทุกข้อ
```

## Prompt เสริม — ตรวจเฉลยด้วยการคำนวณซ้ำ (บังคับทำ ห้ามข้าม)

โจทย์เฉลยผิดข้อเดียว ทำลายความน่าเชื่อถือของเว็บทั้งเว็บ ให้ตรวจด้วย **AI อีกตัว** ทุกชุด

```
นี่คือชุดโจทย์ 12 ข้อ เรื่อง <<กฎของไซน์>> ที่ร่างด้วย AI
หน้าที่ของคุณคือ "ผู้ตรวจข้อสอบ" ไม่ใช่คนแต่งโจทย์ ห้ามเขียนโจทย์ใหม่

ทำตามนี้ทุกข้อ
1. แก้โจทย์ด้วยตัวเองจากศูนย์ โดยไม่ดู solution_steps ที่ให้มา
   แล้วเทียบว่าคำตอบที่ทำเองตรงกับ is_answer: true ไหม
2. ถ้าเป็นข้อ numeric ให้คำนวณซ้ำและระบุค่าที่ได้
3. ตรวจ template: แทนค่ากลางช่วงในทุกตัวแปร แล้วคำนวณ answer_expr
   ตรวจว่าได้ค่าตรงกับคำตอบของโจทย์ต้นแบบ และไม่มีกรณีที่ constraints ปล่อยให้โจทย์พัง
   (เช่น หารศูนย์ รากติดลบ มุมรวมเกิน 180 องศา คำตอบติดลบในโจทย์หาความยาว)
4. ตรวจว่า distractor ทุกตัวเป็นค่าที่ "เกิดจากความผิดพลาดจริง" ไม่ใช่เลขสุ่ม
   และไม่มี distractor ตัวใดที่ถูกต้องด้วย (ข้อสอบมีคำตอบถูกได้ตัวเดียว)
5. ตรวจว่า difficulty ตรงกับ difficulty_signals ตามตาราง C.3
6. ตรวจว่า hints ระดับ 3 ไม่ได้เฉลยคำตอบไปแล้ว
6b. ตรวจ steps_tpl: แทนค่ากลางช่วงลงในทุกขั้น อ่านทวนว่าตัวเลขสอดคล้องกันและได้คำตอบเดียวกัน
6c. ตรวจ hints_tpl ทั้ง 3 ข้อว่าไม่มีค่าใดเท่ากับคำตอบ เมื่อแทนค่ากลางช่วง
7. ตรวจว่าโจทย์กำกวมหรือไม่ — มีตีความได้หลายทางจนตอบได้หลายคำตอบไหม

ตอบเป็นตาราง:
[id] [ผลตรวจ: ผ่าน / เฉลยผิด / template ผิด / โจทย์กำกวม / ความยากไม่ตรง] [คำตอบที่ถูกต้องคือ] [สิ่งที่ต้องแก้]

ท้ายสุดสรุปว่า มีกี่ข้อผ่าน กี่ข้อต้องแก้

<<วาง JSON ชุดโจทย์ที่นี่>>
```

## ปรับ prompt ตามชนิดวิชา

| วิชา | สิ่งที่ต้องเปลี่ยน |
|---|---|
| ฟิสิกส์ / เคมี | บังคับใส่หน่วยทุกที่ เพิ่ม quality_rule ว่า "ค่าที่สุ่มต้องสมจริงทางกายภาพ" (เช่น ความเร็วรถไม่เกิน 200 km/h, pH อยู่ 0–14) และให้มี distractor ที่มาจากการลืมแปลงหน่วยอย่างน้อย 1 ตัวทุกข้อ |
| ชีววิทยา | `template` ส่วนใหญ่เป็น `null` ให้ใช้ `"choice"` type สุ่มตัวอย่างสิ่งมีชีวิต/อวัยวะแทนตัวเลข และเพิ่มจำนวนข้อเป็น 20 |
| ภาษาไทย / สังคม | `template: null` แต่งข้อละเอียด 20 ข้อ และต้องระบุใน `style_ref.note` ว่าเนื้อหาอ้างอิงจากไหน ข้อที่มีตัวบทกฎหมาย/ปี พ.ศ. ให้ตั้ง `review_status` เป็น `"ai_draft_needs_fact_check"` |
| ภาษาอังกฤษ | โจทย์ต้องมีบทอ่านของตัวเอง (แต่งขึ้นใหม่) ห้ามใช้บทอ่านจากข้อสอบจริงหรือหนังสือ ใช้ `"choice"` สุ่มคำศัพท์ในแม่แบบได้ |
| TGAT2 (ตัวเลข/มิติสัมพันธ์) | ทำ `template` ได้ดีที่สุดในบรรดาทุกวิชา ควรบังคับให้ทุกข้อมี template |
| TGAT2 (มิติสัมพันธ์) | หัวข้อพับกล่องมี `provider` เขียนไว้แล้ว ให้ใช้แบบ `provider` ตาม C.6 **ห้ามเขียน `answer_expr`** เพราะคำตอบเป็นชื่อหน้า ไม่ใช่ตัวเลข |
| TGAT3 (สมรรถนะการทำงาน) | ใช้ `format: "mcq4_tiered"` เป็นหลัก (ดู C.8) เพราะผังสอบให้คะแนนลดหลั่น 0.25-1.00 ไม่ใช่ถูก/ผิด `solution_steps` ต้องอธิบาย **เกณฑ์การตัดสิน** ว่าทำไมตัวเลือกนี้ดีกว่า ไม่ใช่การคำนวณ และ `template: null` |
| TPAT2 / TPAT4 | **ไม่มีภาคปฏิบัติ** ทั้งสองวิชาเป็นปรนัยล้วนตามผังสอบทางการ TPAT2 ใช้ `mcq4` TPAT4 ใช้ `mcq5` **ห้ามใช้ `short_answer` หรือสร้างเกณฑ์ให้คะแนนตัวเองสำหรับการวาด** เพราะไม่มีสิ่งนี้ในข้อสอบ |
| TPAT4 (มิติสัมพันธ์) | ส่วนนี้ได้ข้อละ 2.25 คะแนน มากกว่าส่วนอื่นกว่าสองเท่า ควรแต่งโจทย์ให้มากและละเอียดกว่าส่วนอื่น |
