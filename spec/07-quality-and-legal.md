# ส่วน 1 — ลิขสิทธิ์ข้อสอบ

> **อัปเดต:** เว็บจะมีคลังข้อสอบจริง (ฟีเจอร์ C) ด้วย
> วิธีทำให้ได้ประโยชน์เต็มที่และยังเปลี่ยนระดับการเปิดเผยได้ภายหลัง อยู่ใน `09-real-exam-papers.md` ข้อ 1
> ส่วนด้านล่างนี้ยังใช้กับ **โจทย์ในฟีเจอร์ B** ซึ่งต้องแต่งขึ้นใหม่ 100% เหมือนเดิม

## ข้อเท็จจริงที่ต้องรู้
ข้อสอบ TGAT / TPAT / A-Level เป็นงานที่ **มีลิขสิทธิ์** ของ ทปอ. / สทศ. ตามกรณี
การนำข้อสอบจริงมาเผยแพร่ทั้งข้อบนเว็บที่เปิดสาธารณะ (ยิ่งถ้ามีรายได้) มีความเสี่ยงทางกฎหมาย
ไม่ว่าจะได้ไฟล์มาจากที่ใดก็ตาม

## แนวทางที่ปลอดภัยและเป็นจุดแข็งทางธุรกิจด้วย

| ทำได้ | ห้ามทำ |
|---|---|
| ใช้ข้อสอบจริง **เป็นข้อมูลภายใน** เพื่อวิเคราะห์ว่าออกหัวข้ออะไร ยากแค่ไหน ถามแบบไหน | เผยแพร่ข้อสอบจริงทั้งข้อ หรือดัดแปลงแค่เปลี่ยนตัวเลข |
| แต่งโจทย์ขึ้นใหม่ทั้งข้อในแนวเดียวกัน แล้วระบุว่า "แนวข้อสอบปี 2567" | อ้างว่าเป็น "ข้อสอบจริงปี 2567" |
| อ้างอิงเชิงบรรณานุกรมว่าอ้างแนวจากข้อสอบปีใด ข้อใด (ใน `style_ref`) | สแกน/แคปรูปข้อสอบมาลง |
| เผยแพร่ **ผังการสอบ** (จำนวนข้อ เวลา สัดส่วน) เพราะเป็นข้อมูลสาธารณะจาก ทปอ. | คัดลอกเฉลยละเอียดจากหนังสือติวของคนอื่น |

> **นี่ไม่ใช่แค่เรื่องกฎหมาย แต่เป็นจุดขาย**
> โจทย์ที่แต่งใหม่ + สุ่มตัวเลขได้ไม่จำกัด แปลว่าผู้ใช้ **จำข้อไม่ได้** ต้องคิดจริงทุกครั้ง
> ต่างจากเว็บที่มีแต่ข้อสอบเก่า ซึ่งเด็กทำรอบสองก็จำคำตอบได้แล้ว

## สิ่งที่ต้องมีบนเว็บ
1. หน้า "เกี่ยวกับโจทย์" อธิบายชัดเจนว่าโจทย์ทั้งหมดแต่งขึ้นใหม่ ไม่ใช่ข้อสอบจริง
2. ถ้าจะแสดงคะแนนต่ำสุด/สัดส่วนคณะ ต้องอ้างแหล่งที่มาและวันที่ดึงข้อมูล
3. ถ้ามีคนส่งเนื้อหาเข้ามา (ห้องเฉลยชุมชน) ต้องมีข้อตกลงการใช้งานและช่องทางแจ้งลบ

> เอกสารนี้เขียนจากหลักการทั่วไป **ไม่ใช่คำแนะนำทางกฎหมาย**
> ถ้าเว็บเริ่มมีรายได้ ควรให้นักกฎหมายดูข้อตกลงการใช้งานหนึ่งรอบ

# ส่วน 2 — คุณภาพ: อะไรที่ปล่อยผ่านไม่ได้

## ระดับความเสียหายของข้อผิดพลาด (เรียงจากร้ายแรงสุด)

| อันดับ | ประเภท | ทำไมร้ายแรง |
|---|---|---|
| 0 | **ข้อสอบ "จริง" ที่ AI แต่งขึ้นเอง** | ร้ายแรงที่สุดในทุกกรณี ผู้ใช้เชื่อว่าเป็นของจริง พอเทียบกับต้นฉบับแล้วไม่ตรง = เว็บหมดความน่าเชื่อถือทันที และ validator จับไม่ได้เพราะฟอร์แมตถูกทุกอย่าง — กันด้วยกฎในไฟล์ 09 ข้อ 0 และขั้นที่ 4 ของไฟล์ 09 ข้อ 6 |
| 1 | **เนื้อหาบทเรียนผิด** | ผู้ใช้จำไปตอบข้อสอบจริง เสียหายถึงอนาคตเขา และเว็บเสียความน่าเชื่อถือถาวร |
| 2 | **เฉลยโจทย์ผิด** | ผู้ใช้เข้าใจว่าตัวเองผิดทั้งที่ทำถูก บั่นทอนความมั่นใจ |
| 3 | **โจทย์แม่แบบพัง** (สุ่มออกมาแล้วโจทย์ไม่มีคำตอบ / คำตอบไม่อยู่ในตัวเลือก) | เกิดซ้ำได้เรื่อย ๆ อัตโนมัติ ข้อเดียวที่พังสร้างความเสียหายได้เป็นร้อยครั้ง |
| 4 | โจทย์กำกวม ตอบได้หลายคำตอบ | ผู้ใช้เสียเวลาและเสียความรู้สึก |
| 5 | ความยากไม่ตรงกับที่ระบุ | ระบบวิเคราะห์จุดอ่อนเพี้ยน |
| 6 | คำผิด/จัดรูปแบบเพี้ยน | น่ารำคาญแต่แก้ง่าย |

**อันดับ 1–3 ต้องไม่หลุดขึ้นเว็บเลย** ต้องผ่านการตรวจก่อน

## ระบบตรวจ 4 ชั้น (ทำทุกชั้น อย่าข้าม)

### ชั้น 1 — validator ตรวจฟอร์แมต (สคริปต์อัตโนมัติ)
ให้ Codex/Claude Code เขียนสคริปต์ตรวจ:
- JSON parse ได้ ฟิลด์บังคับครบ ชนิดข้อมูลถูก
- `topic_id` ทุกตัวมีอยู่จริงในผังหัวข้อ
- `id` ไม่ซ้ำกันทั้งโปรเจกต์
- MCQ มี `is_answer: true` ตัวเดียว
- `distractor_reasons` ครบทุก index ที่ผิด
- `hints` มี 3 ตัว
- `requires` ไม่มีวงวน (ตรวจ DAG)
- `difficulty` สอดคล้องกับ `difficulty_signals` ตามตาราง C.3

### ชั้น 2 — รัน template จริง (สคริปต์อัตโนมัติ) ⭐ สำคัญที่สุด
สุ่มค่าจาก template **ข้อละ 200 ครั้ง** แล้วเช็คทุกครั้งว่า:
- คำนวณ `answer_expr` ได้ ไม่ error (ไม่หารศูนย์ ไม่รากติดลบ)
- ผลลัพธ์ผ่าน `quality_rules` ทุกข้อ
- ตัวเลือกทุกตัวไม่ซ้ำกันหลังปัดทศนิยม
- ไม่มี distractor ตัวใดมีค่าเท่ากับคำตอบ
- คำตอบไม่หลุดช่วงที่สมจริง

**ถ้าสุ่ม 200 ครั้งแล้วพังแม้แต่ครั้งเดียว ให้ถือว่าข้อนั้นไม่ผ่าน** ต้องกลับไปแก้ `constraints`
นี่คือขั้นที่แยก "ระบบสร้างโจทย์ที่ใช้งานได้จริง" ออกจาก "ระบบที่พังเงียบ ๆ"

### ชั้น 3 — AI ตัวที่สองตรวจเนื้อหา
ใช้ prompt ตรวจในไฟล์ `05-prompt-lesson.md` และ `06-prompt-problems.md`
**ใช้โมเดลต่างค่ายกับตัวที่เขียน** (GPT เขียน -> Claude ตรวจ) เพราะโมเดลเดิมมักมองไม่เห็นข้อผิดของตัวเอง

### ชั้น 4 — คนตรวจ
| เนื้อหาประเภท | ใครควรตรวจ | ตรวจแค่ไหน |
|---|---|---|
| คณิต/ฟิสิกส์/เคมี ที่คำนวณได้ | ชั้น 1–3 จับได้เกือบหมด | คนสุ่มตรวจ 20% |
| ชีววิทยา | AI มักผิดรายละเอียด | คนตรวจทุกบทเรียน |
| **สังคม ประวัติศาสตร์ กฎหมาย ปี พ.ศ. ชื่อบุคคล** | AI ผิดบ่อยที่สุดและ validator จับไม่ได้ | **คนตรวจ 100% เทียบแหล่งอ้างอิง** |
| ภาษาไทย (คำประพันธ์ ฉันทลักษณ์) | AI มักนับสัมผัสผิด | คนตรวจ 100% |
| TGAT3 / TPAT1 (จริยธรรม การตัดสินใจ) | ไม่มีคำตอบถูกทางคณิต | คนตรวจ 100% |

เปลี่ยน `review_status` จาก `"ai_draft"` เป็น `"human_verified"` **เฉพาะเมื่อคนตรวจแล้วจริง**
และ **เว็บต้องแสดงเฉพาะ `human_verified` หรือแสดงป้ายเตือนว่า "ร่างโดย AI ยังไม่ผ่านการตรวจ"**

# ส่วน 3 — สิ่งที่ต้องมีบนเว็บตั้งแต่วันแรก

| สิ่งที่ต้องมี | เหตุผล |
|---|---|
| **ปุ่ม "รายงานว่าโจทย์/เนื้อหานี้ผิด"** ทุกหน้า | ผู้ใช้คือ validator ชั้นที่ 5 ที่ดีที่สุดและฟรี ถ้าไม่มีปุ่มนี้ เขาจะเลิกใช้เว็บเงียบ ๆ แทนที่จะบอกคุณ |
| แบบฟอร์มรายงานต้องเลือกได้ว่า: เฉลยผิด / โจทย์กำกวม / เนื้อหาผิด / พิมพ์ผิด / อื่น ๆ | ทำให้จัดลำดับการแก้ได้ |
| ระบบปิดโจทย์ทันที (kill switch) เมื่อมีรายงานเกิน N ครั้ง | กันความเสียหายลาม |
| ป้ายบอกสถานะ `ai_draft` / `human_verified` | ซื่อสัตย์กับผู้ใช้ และลดความเสียหายเมื่อมีผิดหลุด |
| `misconception_tags` เก็บลงฐานข้อมูลตอนผู้ใช้ตอบผิด | เป็นวัตถุดิบของฟีเจอร์วิเคราะห์จุดอ่อนทั้งหมด ถ้าไม่เก็บตั้งแต่แรกจะย้อนเก็บไม่ได้ |

# ส่วน 4 — ข้อผิดพลาดที่ AI ทำบ่อยในงานนี้ (ให้เฝ้าระวังเฉพาะจุด)

| AI มักทำผิดแบบนี้ | วิธีจับ |
|---|---|
| ให้ `difficulty` ตามความรู้สึก ไม่ตรงกับ `difficulty_signals` | validator ตรวจตามตาราง C.3 |
| `answer_expr` ในแม่แบบไม่ตรงกับเฉลยของโจทย์ต้นแบบ | ชั้น 2 รันจริง |
| `constraints` หลวม ทำให้สุ่มได้โจทย์ที่ไม่มีคำตอบ | ชั้น 2 สุ่ม 200 ครั้ง |
| distractor เป็นเลขสุ่ม แล้วเขียนเหตุผลย้อนหลังให้ดูดี | คนอ่าน `distractor_reasons` แล้วถามว่า "นักเรียนจะพลาดแบบนี้จริงไหม" |
| นับฉันทลักษณ์/สัมผัสในคำประพันธ์ไทยผิด | คนตรวจ |
| ปี พ.ศ. / มาตรากฎหมาย / ชื่อบุคคล มั่ว แต่เขียนอย่างมั่นใจ | คนตรวจเทียบแหล่งอ้างอิง 100% |
| แปลงหน่วยผิดในโจทย์ฟิสิกส์/เคมี | ชั้น 2 + `quality_rules` เรื่องช่วงค่าที่สมจริง |
| `requires` ใส่เกินจำเป็นจนผังรัดตัว | ตรวจว่า leaf ที่มี requires เกิน 3 ตัว มีจริงกี่ตัว |
| อ้างว่าเนื้อหา "ออกสอบทุกปี" โดยไม่มีข้อมูล | ต้องมี `confidence: "low"` กำกับ |
