## 4. ลำดับวิชาที่ควรทำ (ทำทุกวิชา แต่เรียงลำดับให้ได้ผู้ใช้เร็วที่สุด)

| รอบ | กลุ่ม | วิชา (ตามลำดับที่ทำ) | เหตุผล |
|---|---|---|---|
| **1** | **TGAT ครบ 3 พาร์ท** | TGAT2 -> TGAT1 -> TGAT3 | ผู้สมัคร TCAS **ทุกคน** ต้องสอบ ได้ผู้ใช้กว้างสุด |
| **2** | **TPAT ครบ 5 วิชา** | TPAT3 -> TPAT1 -> TPAT5 -> TPAT2 -> TPAT4 | คนกลุ่มนี้หาที่ฝึกยากที่สุด = จุดแข็งที่เว็บอื่นไม่มี |
| **3** | **A-Level 16 วิชา** | คณิต 61 -> ฟิสิกส์ -> เคมี -> ชีวะ -> อังกฤษ -> ไทย -> สังคม -> คณิต 62 -> วิทย์ 63 -> ภาษาที่ 3 (7 วิชา) | ใหญ่สุด ทำเมื่อ prompt นิ่งแล้ว |

**เหตุผลของลำดับภายในแต่ละรอบ**
- **TGAT2 ก่อน** เพราะเป็นวิชาที่ทำโจทย์แม่แบบได้ดีที่สุดในทุกวิชา ใช้พิสูจน์ว่าระบบสร้างโจทย์ทำงานจริง
  และ validator ตรวจได้เกือบทั้งหมดโดยไม่ต้องพึ่งคน
- **TGAT3 ท้ายสุดของรอบ 1** เพราะเป็นข้อสอบสถานการณ์ที่ไม่มีคำตอบถูกทางคณิต ต้องให้คนตรวจ 100%
- **TPAT3 ก่อนในรอบ 2** เพราะคนสอบเยอะสุดในกลุ่ม TPAT และด้านเชิงกล (เฟือง รอก คาน) ทำแม่แบบด้วยโค้ดได้ดี — ผังสอบเรียกด้านนี้ว่า **ด้านเชิงกลและด้านฟิสิกส์** ไม่ใช่ 'เชิงกล-ไฟฟ้า'
- **TPAT2 กับ TPAT4 ท้ายสุด** เพราะคนสอบน้อยที่สุดในกลุ่ม TPAT — **ไม่ใช่เพราะมีภาคปฏิบัติ** ผังสอบทางการระบุว่าทั้งสองวิชาเป็นปรนัยล้วน (ข้อความเดิมที่เขียนว่ามีภาคปฏิบัติไม่ถูกต้อง แก้แล้ว)
- **A-Level ภาษาที่สาม (ฝรั่งเศส เยอรมัน ญี่ปุ่น เกาหลี จีน บาลี สเปน) ท้ายสุด** เพราะคนสอบน้อยที่สุด

**อย่าทำทุกวิชาพร้อมกัน** ทำวิชาแรกให้จบครบทั้ง 8 ขั้นก่อน เพราะคุณจะได้เรียนรู้ว่า prompt ต้องแก้อะไร
ถ้าทำ 5 วิชาพร้อมกันแล้วเจอว่า prompt มีปัญหา คุณจะต้องรื้องาน 5 วิชา

> prompt ที่กรอกค่าให้ทุกวิชาแล้ว อยู่ในไฟล์ `10-prompt-pack.md` เปิดแล้วคัดลอกใช้ได้เลย

## 5. โหมดผลิตจำนวนมาก (สำคัญ — เพราะคุณอยากได้ทุกวิชา)

### ปริมาณงานจริง
| วิชากลุ่ม | จำนวนวิชา | leaf ต่อวิชา | leaf รวม |
|---|---|---|---|
| วิชาหลัก (คณิต ฟิสิกส์ เคมี ชีวะ สังคม ไทย อังกฤษ) | 7 | ~120 | ~840 |
| TGAT + TPAT | 8 | ~30 | ~240 |
| วิชารอง (คณิต 62, วิทย์ 63, ภาษาที่ 3 x7) | 9 | ~50 | ~450 |
| **รวม** | | | **~1,500 leaf** |

ต่อ 1 leaf ต้องมี: บทเรียน 1 ไฟล์ + โจทย์ 12–20 ข้อ
= **~1,500 บทเรียน และ ~20,000 โจทย์**

### ถ้าทำด้วยมือใน ChatGPT
1,500 บทเรียน × 5 นาที + 1,500 ชุดโจทย์ × 6 นาที ≈ **275 ชั่วโมง** (ยังไม่นับตรวจและแก้)
ทำได้ แต่ต้องมีวินัยมาก — ถ้าทำวันละ 2 ชั่วโมงคือ ~5 เดือน

### วิธีที่ควรทำจริง (3 เฟส)

**เฟส A — จูนด้วยมือ (20–30 leaf แรก)**
ทำด้วยมือใน ChatGPT ตาม prompt 04/05/06 แล้วแก้ prompt ในไฟล์ spec ทุกครั้งที่เจอปัญหา
เป้าหมายคือทำให้ **10 leaf ติดกันผ่าน validator ตั้งแต่รอบแรก** โดยไม่ต้องแก้มือ
ถ้ายังไม่ถึงจุดนั้น **ห้ามขึ้นเฟส B** เพราะจะได้ของเสียเป็นพันไฟล์

**เฟส B — ยิงเป็นชุดด้วย API**
ให้ Codex / Claude Code เขียนสคริปต์:
1. อ่าน `data/topics/*.topics.json` เอา leaf ทั้งหมดที่ `_status.csv` ยังเป็น `todo`
2. ประกอบ prompt จากไฟล์ 05 หรือ 06 โดยเติมข้อมูลของ leaf นั้น
3. เรียก API (เปิด structured output / JSON mode ให้ตอบตาม schema)
4. บันทึกไฟล์ + อัปเดต `_status.csv` + เก็บ log ว่าใช้ prompt เวอร์ชันไหน โมเดลอะไร
5. รัน validator ทันที ถ้าไม่ผ่านให้ทำเครื่องหมายไว้แก้ ไม่ใช่เขียนทับของดี

สคริปต์นี้ต้องมี: จำกัดอัตราการเรียก, ทำต่อจากที่ค้างได้ (resume), และ **โหมด dry-run ทำ 5 ไฟล์ก่อน**

**เฟส C — ตรวจและแก้**
รันชั้น 1–3 ของไฟล์ 07 อัตโนมัติทั้งหมด แล้วคนเข้าไปตรวจเฉพาะที่ระบบตีธงไว้
+ วิชาที่ตารางในไฟล์ 07 ระบุว่าต้องตรวจ 100%

### เรื่องค่าใช้จ่าย
การเรียก API 1,500 + 1,500 ครั้ง ด้วยโมเดลระดับคิดเยอะ **มีค่าใช้จ่ายจริง**
ให้ประมาณราคาก่อนรันเต็ม โดยรัน 10 ไฟล์แล้วดู token ที่ใช้ × 3,000 แล้วคูณราคาต่อ token
เทคนิคลดค่าใช้จ่าย: ใช้ prompt caching (ส่วน schema ที่ส่งซ้ำทุกครั้งจะถูกลง)
และใช้โมเดลถูกกว่าสำหรับวิชาที่ validator ตรวจได้แน่น (คณิต/ฟิสิกส์) แล้วใช้โมเดลแพงกับวิชาที่ต้องเนื้อหาแม่น

## 6. หน้าที่ของ AI แต่ละตัว (สรุป)

| งาน | ใช้อะไร | หมายเหตุ |
|---|---|---|
| ผังหัวข้อ / บทเรียน / โจทย์ | **ChatGPT** (โมเดลคิดเยอะ) | 1 แชต = 1 วิชา แนบ `03-schema.md` ทุกครั้ง |
| ตรวจเนื้อหาและเฉลย | **AI อีกค่าย** (Claude) | ตัวที่เขียนมองไม่เห็นข้อผิดของตัวเอง |

| ยืนยันโครงสอบ สัดส่วนคณะ คะแนนต่ำสุด | **ไม่ใช้ AI เลย** | ดูจาก mytcas.com และประกาศ ทปอ. เท่านั้น |
| ถอดข้อสอบจริงจากไฟล์ + tag หัวข้อ + เขียนเฉลยเอง | **ChatGPT + ไฟล์แนบ** | ต้องแนบไฟล์ต้นฉบับ ห้ามให้นึกเอง (ไฟล์ 09) |
| หาไฟล์ข้อสอบจริง + เทียบว่าถอดถูกต้อง | **ไม่ใช้ AI เลย** | AI ถอด OCR ผิดได้และ validator จับไม่ได้ |

### 7.1 `generate.py` — ผลิตเป็นชุดด้วย Claude API

**ต้องติดตั้งเพิ่มก่อน** `pip install anthropic` และต้องมีคีย์ (`ANTHROPIC_API_KEY`
หรือล็อกอินด้วย `ant auth login`) — ตัวตรวจงานตัวอื่นไม่ต้องติดตั้งอะไร ยังรันได้ทุกเครื่องเหมือนเดิม

| คำสั่ง | ทำอะไร | เสียเงินไหม |
|---|---|---|
| `--plan` | ดูว่าหัวข้อไหนยังไม่มีบทเรียน/โจทย์ | ไม่ |
| `--topic <id> --kind lesson --dry-run` | ประกอบคำสั่งจริง + ประเมินค่าใช้จ่าย | ไม่ |
| `--topic <id> --kind lesson` | ยิงทีละหัวข้อ ใช้ตอนจูนคำสั่ง | ใช่ |
| `--kind problems --batch --limit 20` | ยิงเป็นชุดผ่าน Batches API | ใช่ (ครึ่งราคา) |
| `--collect <batch_id>` | เก็บผลของชุดที่ส่งไว้แล้ว | ไม่ (จ่ายไปแล้ว) |

**ของที่ยิงมาไม่เข้า `data/` อัตโนมัติ** ต้องผ่านสองด่านก่อน
1. `validate.py` — ฟอร์แมตถูกตามสเปค
2. `render_template.py --stress` — แม่แบบรันได้ 200 รอบไม่พัง เฉลยไม่รั่ว

ตรวจในสำเนาชั่วคราวของ `data/` ไม่ใช่ในของจริง ไฟล์ที่ไม่ผ่านไปอยู่
`data/_generate/rejected/` พร้อมผลตรวจว่าติดข้อไหน (โฟลเดอร์นี้ไม่ขึ้น repo)

ไฟล์ที่ **ผ่าน** ทั้งสองด่านก็ยังเป็นแค่ `ai_draft` — **คนต้องอ่านเนื้อหาก่อนเผยแพร่**
เพราะตัวตรวจจับความผิดทางวิชาการ โจทย์กำกวม และปี พ.ศ./ชื่อ/มาตราที่ผิดไม่ได้

สถานะงานและค่าใช้จ่ายทุกครั้งบันทึกไว้ใน `data/_generate/state.json`
จึงหยุดกลางทางแล้วกลับมาทำต่อได้ และย้อนดูได้ว่าใช้เงินไปเท่าไรกับหัวข้อไหน

**สิ่งที่สคริปต์ห้ามทำ ฝังไว้ในโค้ด ไม่ใช่แค่ในคำสั่ง**
- ห้ามเขียนอะไรลง `data/exams/` — คลังข้อสอบจริงต้องมาจากไฟล์ต้นฉบับเท่านั้น
- ไม่ทับไฟล์ที่มีอยู่แล้ว (ถ้าจะทำใหม่ ลบของเดิมเองก่อน)

**รันทั้งสองตัวหลังได้ไฟล์จาก GPT ทุกครั้ง** ก่อนจะเอาไปตรวจด้วยคนหรือด้วย AI ตัวที่สอง
เพราะสองตัวนี้จับข้อผิดพลาดที่คนมองด้วยตาไม่เห็นได้ฟรี

รหัสออกจากโปรแกรม 0 = ผ่าน / 1 = มีรายการต้องแก้ จึงนำไปต่อกับ CI หรือสคริปต์อื่นได้

### ไฟล์ตัวอย่างที่ใส่ไว้ให้แล้ว

`data/` มีไฟล์ตัวอย่างของหัวข้อ `math.trig.sine_law` ครบทั้ง 3 ชนิด (ผังหัวข้อ บทเรียน โจทย์)
ผ่านการตรวจทั้งชั้น 1 และชั้น 2 แล้ว ใช้ได้ 2 อย่าง
1. ทดสอบว่าสคริปต์ทำงานบนเครื่องคุณได้
2. **แนบให้ GPT เป็นตัวอย่างคุณภาพที่ต้องการ** ซึ่งได้ผลดีกว่าอธิบายด้วยคำพูด

**ข้อ 1 และ 2 ควรทำก่อนเริ่มเฟส B** ไม่ใช่ทำทีหลัง
เพราะถ้าผลิตไป 500 ไฟล์แล้วเพิ่งรู้ว่า `answer_expr` ผิดฟอร์แมตกันหมด คือต้องรันใหม่ทั้งหมด
