# 03 — สเปคฟอร์แมตข้อมูล (JSON Schema) — ไฟล์บังคับ

> **แนบไฟล์นี้ให้ AI ทุกครั้งที่สั่งงาน** ถ้าไม่แนบ มันจะคิดชื่อฟิลด์เองและข้อมูลจะนำเข้าระบบไม่ได้
>
> กฎเหล็ก 5 ข้อ
> 1. ตอบเป็น **JSON ที่ parse ได้** เท่านั้น ห้ามมีข้อความอธิบายอยู่นอก JSON
> 2. **ห้ามเพิ่ม ลบ หรือเปลี่ยนชื่อฟิลด์** ถ้าไม่มีข้อมูลให้ใส่ `null` หรือ `[]`
> 3. ฟิลด์ที่มี `*` = **บังคับ** ห้ามขาด
> 4. LaTeX ในสตริง JSON ต้อง escape backslash เป็น `\\` เช่น `"$\\sqrt{2}$"`
> 5. `topic_id` ต้องมีอยู่จริงใน topic tree ที่สร้างไว้แล้ว **ห้ามคิดขึ้นใหม่เอง**

# ส่วน A — TOPIC TREE (ผังหัวข้อ) — ใช้ร่วมกันทั้ง 2 ฟีเจอร์

**ไฟล์:** `data/topics/<subject>.topics.json`

## A.1 โครงไฟล์

```json
{
  "schema_version": "1.0",
  "subject": "math",
  "subject_name_th": "คณิตศาสตร์",
  "exam_codes": ["ALEVEL_61", "ALEVEL_62"],
  "source_note": "อ้างจากผังการสอบ A-Level ปี 2568 และหลักสูตรแกนกลาง 2551 (ปรับปรุง 2560)",
  "topics": []
}
```

## A.2 อ็อบเจกต์ `topic`

| ฟิลด์ | ชนิด | คำอธิบาย |
|---|---|---|
| `id` * | string | รหัสตามกฎใน `01-overview.md` ห้ามซ้ำ ห้ามเปลี่ยนภายหลัง |
| `name_th` * | string | ชื่อไทยที่ผู้ใช้เห็น |
| `name_en` * | string | ชื่ออังกฤษ |
| `kind` * | enum | `"subject"` / `"branch"` / `"leaf"` |
| `parent` * | string หรือ null | `id` ของชั้นบน ชั้นบนสุดใส่ `null` |
| `order` * | int | ลำดับการแสดงในกลุ่มเดียวกัน เริ่ม 1 |
| `grade_band` * | enum | `"m1"`…`"m6"` / `"m_early"` (ม.ต้นรวม) / `"mixed"` |
| `requires` * | string[] | `topic_id` ที่ต้องรู้ก่อน (เฉพาะที่จำเป็นจริง 0–3 ตัว) ใส่ `[]` ถ้าไม่มี |
| `est_minutes` * | int | เวลาเรียนโดยประมาณ (leaf: 10–30) |
| `exam_weight` * | object[] | น้ำหนักในการสอบ ดูรูปแบบด้านล่าง |
| `difficulty_band` * | enum | `"easy"` / `"medium"` / `"hard"` |
| `keywords` * | string[] | คำค้น 3–8 คำ (ไทย/อังกฤษผสมได้) |
| `curriculum_ref` | string หรือ null | ตัวชี้วัดหลักสูตร ถ้าทราบ เช่น `"ค 1.2 ม.4/2"` ไม่ทราบใส่ `null` |
| `notes` | string หรือ null | หมายเหตุสำหรับคนตรวจ |

รูปแบบ `exam_weight`:
```json
[{"exam_code":"ALEVEL_61","frequency":0.05,"typical_items":"1-2 ข้อต่อปี","confidence":"low"}]
```

### กฎของ `requires` (สำคัญต่อฟีเจอร์ "ไต่หาต้นตอความไม่เข้าใจ")
- ใส่เฉพาะสิ่งที่ **ถ้าไม่รู้แล้วเรียนหัวข้อนี้ไม่ได้จริง ๆ**
- ห้ามใส่หัวข้อที่ "รู้ก็ดี" — จะทำให้ผังรัดตัวและระบบวินิจฉัยเพี้ยน
- **ห้ามเป็นวง** (A ต้องการ B, B ต้องการ A) ผังต้องเป็น DAG

### กฎของ `exam_weight.confidence`
ถ้าไม่มีข้อมูลจริงเรื่องความถี่การออกสอบ ให้ใส่ `"confidence": "low"` และประมาณอย่างระมัดระวัง
**ห้ามแต่งตัวเลขความถี่ให้ดูน่าเชื่อ** ค่านี้จะถูกแทนที่ด้วยข้อมูลจริงจากผู้ใช้ภายหลัง

# ส่วน B — LESSON (บทเรียน) — ฟีเจอร์ A: เรียนจาก 0

**ไฟล์:** `data/lessons/<topic_id>.json` (1 leaf = 1 ไฟล์)

**เป้าหมาย:** คนที่ไม่เคยเรียนเรื่องนี้เลย อ่านไฟล์นี้จบแล้วทำโจทย์ระดับ 1–3 ได้ **โดยไม่ต้องเปิดแหล่งอื่น**

## B.1 โครงไฟล์

| ฟิลด์ | ชนิด | คำอธิบาย |
|---|---|---|
| `schema_version` * | string | `"1.0"` |
| `topic_id` * | string | ต้องตรงกับ leaf ใน topic tree |
| `title` * | string | ชื่อบทเรียน (ปกติเท่ากับ `name_th`) |
| `subtitle` * | string | 1 บรรทัดบอกว่าเรียนแล้วทำอะไรได้ |
| `prereq_topic_ids` * | string[] | คัดลอกจาก `requires` ของ topic |
| `objectives` * | string[] | 2–5 ข้อ เขียนแบบวัดผลได้ ("แก้สมการ… ได้" ไม่ใช่ "เข้าใจ…") |
| `est_minutes` * | int | เวลาอ่านจริง |
| `blocks` * | object[] | เนื้อหา เรียงตามลำดับที่ต้องอ่าน (ดู B.2) |
| `glossary` * | object[] | `[{"term_th":"","term_en":"","def_md":""}]` ใส่ `[]` ถ้าไม่มี |
| `common_exam_patterns` * | string[] | 2–4 ข้อ: เรื่องนี้ออกสอบเป็นแนวไหนบ้าง |
| `next_topic_ids` * | string[] | หัวข้อที่ควรเรียนต่อ |
| `sources` * | string[] | อ้างอิงที่ใช้เขียน ถ้าเขียนจากความรู้ทั่วไปใส่ `["ความรู้ทั่วไปตามหลักสูตรแกนกลาง"]` |
| `review_status` * | string | AI ใส่ `"ai_draft"` เสมอ (คนตรวจจะเปลี่ยนเป็น `"human_verified"` เอง) |

## B.2 ชนิดของ `blocks` — ใช้ได้ 7 ชนิดเท่านั้น

ลำดับที่บทเรียนดีควรมี:
`hook` -> `concept` (1–3 บล็อก) -> `formula` (ถ้ามีสูตร) -> `example` (2–3 ข้อ ไล่จากง่ายไปยาก) -> `pitfall` (1–3) -> `summary` -> `check` (2–3)

### 1) `hook` — ปูว่าเรียนไปทำอะไร
```json
{"type":"hook","body_md":"ถ้ารู้แค่ด้าน 2 ด้านกับมุม 1 มุมของสามเหลี่ยมที่ไม่ใช่มุมฉาก จะหาด้านที่เหลือได้ไหม ..."}
```

### 2) `concept` — อธิบายแนวคิด (บล็อกหลัก)
```json
{"type":"concept","heading":"กฎของไซน์บอกอะไร","body_md":"เนื้อหา markdown + LaTeX ...","figures":[]}
```
- `body_md` ยาว 80–350 คำต่อบล็อก ถ้ายาวกว่านั้นให้ซอยเป็นหลาย `concept`
- ต้อง **อธิบายที่มา ไม่ใช่โยนสูตร** คนเริ่มจาก 0 ต้องรู้ว่าทำไมสูตรเป็นแบบนั้น

### 3) `formula` — การ์ดสูตร (1 การ์ด = 1 สูตร)
```json
{
  "type":"formula",
  "name":"กฎของไซน์",
  "formula_tex":"\\frac{a}{\\sin A}=\\frac{b}{\\sin B}=\\frac{c}{\\sin C}=2R",
  "variables":[{"symbol":"a","meaning":"ความยาวด้านตรงข้ามมุม A","unit":"หน่วยความยาว"}],
  "use_when":"รู้ (มุม 2 + ด้าน 1) หรือ (ด้าน 2 + มุมตรงข้ามด้านหนึ่ง)",
  "avoid_when":"รู้ด้าน 3 ด้านแต่ไม่รู้มุมเลย กรณีนี้ต้องใช้กฎของโคไซน์",
  "derivation_md":"ที่มาสั้น ๆ ไม่เกิน 120 คำ",
  "memory_tip":"จำว่า ด้านคู่กับมุมตรงข้ามมันเสมอ"
}
```
- `use_when` และ `avoid_when` **บังคับ** เพราะเป็นสิ่งที่แยก "จำสูตรได้" กับ "ใช้สูตรถูก"

### 4) `example` — ตัวอย่างพร้อมวิธีคิดทีละขั้น
```json
{
  "type":"example",
  "label":"ตัวอย่างที่ 1 (พื้นฐาน)",
  "difficulty":2,
  "stem_md":"สามเหลี่ยม ABC มี $A=40^\\circ$, $B=75^\\circ$, $a=12$ ซม. หา $b$",
  "steps":[
    {"do_md":"ใช้กฎของไซน์: $\\frac{a}{\\sin A}=\\frac{b}{\\sin B}$","why_md":"เพราะรู้มุม 2 มุมและด้านตรงข้ามมุมหนึ่ง ตรงเงื่อนไขการใช้กฎของไซน์"},
    {"do_md":"แทนค่า: $b=\\frac{12\\sin 75^\\circ}{\\sin 40^\\circ}$","why_md":"ย้ายข้างให้ $b$ อยู่ตัวเดียว"},
    {"do_md":"คำนวณ: $b\\approx 18.0$ ซม.","why_md":"ปัดทศนิยม 1 ตำแหน่งตามความละเอียดของโจทย์"}
  ],
  "answer_md":"$b\\approx 18.0$ ซม.",
  "figures":[]
}
```
- **ทุกขั้นต้องมี `why_md`** นี่คือสิ่งที่คนเริ่มจาก 0 ต้องการ ไม่ใช่แค่รู้ว่าทำอะไร แต่ทำไม

### 5) `pitfall` — กับดักที่คนพลาดบ่อย
```json
{
  "type":"pitfall",
  "title":"ลืมกรณีกำกวม",
  "wrong_md":"เมื่อรู้ $a, b, A$ แล้วสรุปว่ามีสามเหลี่ยมได้แบบเดียว",
  "why_wrong_md":"$\\sin\\theta$ ให้ค่าเท่ากันได้ทั้งมุมแหลมและมุมป้าน จึงอาจมีสามเหลี่ยมได้ 2 แบบ",
  "correct_md":"ต้องเช็คทั้ง $B$ และ $180^\\circ-B$ ว่าอันไหนทำให้ผลรวมมุมไม่เกิน $180^\\circ$",
  "misconception_tag":"ambiguous_case"
}
```
- `misconception_tag` ใช้ snake_case อังกฤษ **ต้องตรงกับที่ใช้ในไฟล์โจทย์** (ส่วน C)

### 6) `summary` — สรุป
```json
{"type":"summary","bullets_md":["กฎของไซน์ใช้เมื่อ...","ระวังกรณี SSA...","ถ้ารู้ด้าน 3 ด้านให้ใช้..."]}
```

### 7) `check` — เช็คความเข้าใจ (ง่ายกว่าข้อสอบจริง มีไว้ยืนยันว่าอ่านเข้าใจ)
```json
{
  "type":"check",
  "question_md":"สามเหลี่ยมที่รู้ด้าน 3 ด้าน ควรใช้กฎใด",
  "choices":["กฎของไซน์","กฎของโคไซน์","ทฤษฎีบทพีทาโกรัส","ใช้ไม่ได้ทั้งสามข้อ"],
  "answer_index":1,
  "explain_md":"กฎของไซน์ต้องรู้มุมอย่างน้อย 1 มุม เมื่อรู้แต่ด้านจึงต้องใช้กฎของโคไซน์"
}
```
- `answer_index` **นับจาก 0**

## B.3 ฟอร์แมต `figures` (ใช้ได้ทั้ง lesson และ problem)

```json
"figures":[
  {"id":"fig1","type":"svg","alt":"สามเหลี่ยม ABC มีมุม A 40 องศา","svg":"<svg viewBox=\"0 0 200 150\">...</svg>","caption":"สามเหลี่ยม ABC"},
  {"id":"fig2","type":"needs_drawing","alt":"กราฟไซน์ 1 คาบ","description":"กราฟ y=sin x ช่วง 0 ถึง 2pi ทำเครื่องหมายจุดตัดแกน x","caption":null}
]
```
- อ้างรูปในเนื้อหาด้วย `[[fig1]]` ในตำแหน่งที่ต้องการให้รูปปรากฏ
- SVG ห้ามกำหนดสีเส้นเป็นสีดำตายตัว ให้ใช้ `currentColor` เพื่อให้ใช้ได้ทั้งธีมสว่างและมืด

# ส่วน C — PROBLEM (โจทย์) — ฟีเจอร์ B: วัดตัวเอง

**ไฟล์:** `data/problems/<topic_id>.json`

> **ไฟล์นี้ใช้กับโจทย์ที่แต่งขึ้นใหม่เท่านั้น**
> ข้อสอบจริง (ฟีเจอร์ C) ใช้ฟอร์แมตต่างกันและเก็บใน `data/exams/` — ดู `09-real-exam-papers.md`
> **ห้ามเอาข้อสอบจริงมาใส่ใน `data/problems/`** เพราะระบบจะเอาไปสุ่มสร้างใหม่และอ้างว่าเป็นโจทย์ของเรา

## C.1 โครงไฟล์

```json
{
  "schema_version": "1.0",
  "topic_id": "math.trig.sine_law",
  "problems": []
}
```

## C.2 อ็อบเจกต์ `problem`

| ฟิลด์ | ชนิด | คำอธิบาย |
|---|---|---|
| `id` * | string | `prob.<topic_id>.<4หลัก>` เช่น `prob.math.trig.sine_law.0001` |
| `topic_ids` * | string[] | ทุกหัวข้อที่ข้อนี้ใช้ (ข้อผสมมีหลายตัว) |
| `primary_topic_id` * | string | หัวข้อหลัก 1 ตัว |
| `exam_code` * | string หรือ null | สนามสอบที่แนวนี้ออก เช่น `"ALEVEL_61"` |
| `origin` * | enum | `"original"` เท่านั้น (ดูเหตุผลใน `07-quality-and-legal.md`) |
| `style_ref` * | object หรือ null | `{"year":2567,"item_no":12,"note":"แนวเดียวกัน ไม่ใช่ข้อสอบจริง"}` |
| `format` * | enum | `"mcq4"` / `"mcq5"` / `"numeric"` / `"multi_select"` / `"matching"` / `"ranking"` / `"short_answer"` | — `"mcq4_tiered"` ใช้กับข้อสอบสถานการณ์ที่ให้คะแนนลดหลั่น ดู C.8
| `difficulty` * | int 1–5 | ตามเกณฑ์ข้อ C.3 |
| `difficulty_signals` * | object | หลักฐานประกอบความยาก (ข้อ C.3) |
| `est_seconds` * | int | เวลาที่ควรใช้ |
| `stem_md` * | string | ตัวโจทย์ |
| `figures` * | object[] | ตามฟอร์แมต B.3 ใส่ `[]` ถ้าไม่มี |
| `choices` * | object[] หรือ null | เฉพาะ MCQ: `[{"md":"...","is_answer":false}]` ต้องมี `is_answer:true` ตัวเดียว |
| `answer_numeric` * | object หรือ null | เฉพาะ numeric: `{"value":18.0,"tolerance":0.1,"unit":"ซม."}` |
| `solution_steps` * | object[] | `[{"do_md":"","why_md":""}]` อย่างน้อย 2 ขั้น ทุกขั้นต้องมี `why_md` |
| `answer_explanation_md` * | string | สรุปคำตอบ 1–3 บรรทัด |
| `hints` * | string[3] | **ต้องมี 3 ระดับเสมอ** [1] ชี้ว่าเป็นเรื่องอะไร [2] ชี้สูตร/แนวทาง [3] ทำขั้นแรกให้ดู (ยังไม่เฉลย) |
| `distractor_reasons` * | object | index ตัวเลือกผิด -> เหตุผลที่คนเลือกผิด เช่น `{"0":"ใช้ sin แทน cos","2":"ลืมแปลงหน่วย"}` |
| `misconception_tags` * | string[] | snake_case ต้องใช้ชื่อเดียวกับใน lesson `pitfall` |
| `template` * | object หรือ null | โจทย์แม่แบบ (ข้อ C.4) ถ้าทำไม่ได้ใส่ `null` แล้วระบุเหตุผลใน `template_note` |
| `template_note` | string หรือ null | ถ้า `template` เป็น `null` ให้บอกว่าทำไม |
| `calculator_allowed` * | bool | ข้อนี้ต้องใช้เครื่องคิดเลขไหม |
| `review_status` * | string | AI ใส่ `"ai_draft"` เสมอ |

## C.3 เกณฑ์ความยาก — ต้องวัดได้ ไม่ใช่รู้สึก

**นี่คือหัวใจของ "โจทย์แต่งใหม่ที่ยากประมาณเดียวกัน"**
ห้ามให้ AI ให้คะแนนความยากตามความรู้สึก ต้องกรอก `difficulty_signals` ก่อน แล้วค่อยสรุป `difficulty` จากตาราง

```json
"difficulty_signals": {
  "steps_count": 3,
  "topics_count": 1,
  "needs_insight": false,
  "heavy_computation": false,
  "trap_present": true,
  "reading_load": "low"
}
```

| ฟิลด์ | ความหมาย |
|---|---|
| `steps_count` | จำนวนขั้นตอนคำนวณ/ให้เหตุผลที่ข้ามไม่ได้ |
| `topics_count` | จำนวนหัวข้อย่อยที่ต้องใช้ร่วมกัน |
| `needs_insight` | ต้องมองเห็นทริกพิเศษถึงจะแก้ได้ไหม (`true` = ไม่ตรงไปตรงมา) |
| `heavy_computation` | เลขเยอะ/ยุ่งจนเสี่ยงพลาดไหม |
| `trap_present` | มีกับดักที่จงใจวางไว้ไหม (หน่วยไม่ตรง เงื่อนไขซ่อน) |
| `reading_load` | `"low"` / `"medium"` / `"high"` ความยากของการตีความโจทย์ |

**ตารางแปลงเป็น `difficulty`:**

| ระดับ | เกณฑ์ |
|---|---|
| **1** | `steps_count`=1, `topics_count`=1, ไม่มี insight/กับดัก แทนค่าในสูตรตรง ๆ ตัวเลขสวย |
| **2** | `steps_count`=1–2, `topics_count`=1, อาจมีการจัดรูปหรือแปลงหน่วย 1 ครั้ง |
| **3** | `steps_count`=2–3 **หรือ** มีกับดัก 1 จุด ต้องเลือกสูตรเองว่าจะใช้อะไร |
| **4** | `steps_count`>=3 **และ** (`topics_count`>=2 **หรือ** `reading_load`=high **หรือ** `heavy_computation`=true) |
| **5** | `needs_insight`=true ต้องมีไอเดียเฉพาะ ระดับข้อท้าย ๆ ของข้อสอบหรือระดับ สอวน. |

**สัดส่วนที่ต้องแต่งต่อ 1 หัวข้อย่อย (ถ้าไม่ได้สั่งเป็นอย่างอื่น): 12 ข้อ**

| ระดับ | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| จำนวนข้อ | 2 | 3 | 4 | 2 | 1 |

## C.4 `template` — โจทย์แม่แบบ (สิ่งที่ทำให้สร้างโจทย์ใหม่ได้ไม่จำกัด)

**แนวคิด:** ระบบสุ่มค่าตัวแปร แล้ว **คำนวณเฉลยด้วยโค้ด** ไม่ใช่ให้ AI เดา เฉลยจึงถูกเสมอ

```json
"template": {
  "vars": [
    {"name":"A","type":"int","range":[30,70],"step":5,"unit":"องศา"},
    {"name":"B","type":"int","range":[40,90],"step":5,"unit":"องศา"},
    {"name":"a","type":"int","range":[6,20],"step":1,"unit":"ซม."}
  ],
  "constraints": [
    "A + B < 170",
    "abs(A - B) >= 10",
    "abs(180 - 2*A - B) >= 5",
    "abs(A + B - 90) >= 5",
    "B != 90"
  ],
  "stem_tpl": "สามเหลี่ยม ABC มี $A={A}^\\circ$, $B={B}^\\circ$ และ $a={a}$ ซม. จงหาความยาวด้าน $b$",
  "answer_expr": "a * sin(radians(B)) / sin(radians(A))",
  "answer_round": 1,
  "answer_unit": "ซม.",
  "distractors": [
    {"expr":"a * sin(radians(A)) / sin(radians(B))","reason":"สลับตัวเศษตัวส่วน"},
    {"expr":"a * cos(radians(B)) / cos(radians(A))","reason":"ใช้ cos แทน sin"},
    {"expr":"a * sin(radians(B)) / sin(radians(180 - A - B))","reason":"ใช้มุม C แทนมุม A"}
  ],
  "quality_rules": [
    "คำตอบต้องอยู่ระหว่าง 1 ถึง 100",
    "ตัวเลือกทุกตัวต้องไม่ซ้ำกันเมื่อปัดทศนิยมแล้ว",
    "ตัวเลือกผิดต้องไม่ติดลบ"
  ]
}
```

### กฎการเขียน `answer_expr` และ `distractors[].expr`
เขียนเป็นนิพจน์ที่ **รันได้ใน Python** (ระบบจะ eval แบบจำกัดสิทธิ์) ใช้ได้เฉพาะ:
- ตัวดำเนินการ `+ - * / ** % ( )`
- ฟังก์ชัน `sqrt sin cos tan asin acos atan radians degrees log log10 exp abs round floor ceil pi e min max`
- ชื่อตัวแปรจาก `vars` เท่านั้น
- **ห้าม** ใช้ฟังก์ชันอื่น เรียกไลบรารี หรือเขียนโค้ดหลายบรรทัด

### กฎการเขียน `constraints` และ `quality_rules`
- `constraints` เป็นเงื่อนไขที่ตรวจ **ก่อน** คำนวณคำตอบ ใช้ตัวเปรียบเทียบ (`< <= > >= == !=`)
  และ `and` / `or` ได้ นอกเหนือจากตัวดำเนินการและฟังก์ชันในรายการข้างบน
- `quality_rules` เป็นเงื่อนไขที่ตรวจ **หลัง** คำนวณคำตอบและตัวเลือกครบแล้ว
  ถ้าไม่ผ่านข้อใด ระบบจะ **สุ่มค่าชุดใหม่** ไม่ใช่แสดงโจทย์นั้นออกไป
- `constraints` ต้องกันกรณีที่ทำให้ **ตัวเลือกลวงไปซ้ำกับคำตอบ** ด้วย ไม่ใช่กันแค่การคำนวณ error
  ตัวอย่างจริงจากแม่แบบข้างบน: ถ้า $C=180-A-B$ ดันเท่ากับ $A$ ตัวเลือกลวง "ใช้มุม C แทนมุม A"
  จะได้ค่าเท่ากับคำตอบพอดี จึงต้องมีเงื่อนไข `abs(180 - 2*A - B) >= 5`
  และถ้า $B=90$ จะได้ $\\cos B = 0$ ทำให้ตัวเลือกลวงเป็น 0 จึงต้องตัดค่า 90 ออกจากช่วง
- อีกกรณีที่พบจากการสุ่มจริง: ถ้า $A+B=90$ ตัวเลือกลวง "สลับตัวเศษตัวส่วน" กับ "ใช้ cos แทน sin"
  จะได้ค่าเท่ากันพอดี (เพราะ $\\sin 2A=\\sin 2B$) จึงต้องมีเงื่อนไข `abs(A + B - 90) >= 5`
- **บทเรียนสำคัญ:** เงื่อนไขพวกนี้มองด้วยตาไม่เห็น ต้องรู้จากการ **รันสุ่มจริง 200 ครั้ง**
  ตามชั้นที่ 2 ในไฟล์ `07-quality-and-legal.md` เท่านั้น จึงห้ามข้ามขั้นนั้น

### `display` (ไม่บังคับ) — ค่าที่คำนวณไว้แสดงในโจทย์

บางโจทย์ ตัวเลขที่ปรากฏในโจทย์ไม่ใช่ตัวแปรที่สุ่มโดยตรง แต่คำนวณมาจากตัวแปรที่สุ่ม
เช่นอนุกรมที่ประกาศแค่พจน์แรก `a1` กับผลต่าง `d` แต่ต้องแสดงพจน์ที่ 2, 3, 4 ในโจทย์

```json
"display": {
  "t2": "a1 + d",
  "t3": "a1 + 2*d",
  "t4": "a1 + 3*d"
},
"stem_tpl": "${a1}, {t2}, {t3}, {t4}, ?$"
```

- คำนวณตามลำดับที่เขียน ตัวหลังอ้างตัวหน้าได้
- ใช้ชื่อจาก `display` ใน `answer_expr`, `distractors`, `quality_exprs` และ `constraints` ได้
- ชื่อต้องไม่ซ้ำกับชื่อใน `vars`
- ห้ามใช้แทนตัวแปรที่ควรสุ่มจริง — ถ้าค่าใดสุ่มได้อิสระ ให้ประกาศใน `vars`

### ระบบต้องไม่ออกโจทย์ที่ค่าตัวแปรซ้ำกันในชุดเดียว

แม่แบบหนึ่งอันสุ่มค่าได้จำกัด เช่น `a1` 13 ค่า และ `d` 6 ค่า = 78 ชุด
ถ้าสุ่มแบบไม่จำอะไรเลย ชุดฝึก 10 ข้อจะมีข้อซ้ำกันได้ (พบจริงตอนทดสอบ)

**ตัวสร้างโจทย์ต้องจำชุดค่าที่ออกไปแล้วและไม่ออกซ้ำภายในชุดเดียวกัน**
และเวลาออกแบบแม่แบบ ให้ประมาณจำนวนชุดค่าที่เป็นไปได้ให้มากกว่าจำนวนข้อที่จะออกอย่างน้อย 10 เท่า
`scripts/render_template.py` ทำเรื่องนี้ให้แล้ว และจะรายงานถ้าสร้างไม่ครบจำนวนที่ขอ

### `quality_exprs` (ไม่บังคับ แต่แนะนำ) — เงื่อนไขที่เครื่องตรวจได้

`quality_rules` เป็นข้อความภาษาไทยให้คนอ่าน สคริปต์ตรวจอัตโนมัติไม่ได้
ถ้าต้องการให้ตรวจอัตโนมัติ ให้เขียนเงื่อนไขเดียวกันเป็นนิพจน์ใน `quality_exprs` ด้วย
ใช้ชื่อตัวแปรจาก `vars` ได้ บวกกับตัวแปรพิเศษ `answer` (ค่าคำตอบหลังปัดทศนิยมแล้ว)

```json
"quality_rules": ["คำตอบต้องอยู่ระหว่าง 1 ถึง 100"],
"quality_exprs": ["answer >= 1", "answer <= 100"]
```

### กฎความน่าเชื่อของตัวเลือกลวง (สคริปต์ตรวจให้อัตโนมัติ)

`scripts/render_template.py` จะตีธงเมื่อค่าที่สุ่มได้ทำให้ตัวเลือกลวง:
- **ห่างจากคำตอบเกิน 5 เท่า** (มากกว่า `answer x 5` หรือน้อยกว่า `answer / 5`)
- **ติดลบหรือเป็นศูนย์** ในโจทย์ที่คำตอบเป็นบวก

เพราะนักเรียนตัดทิ้งได้โดยไม่ต้องคำนวณ ข้อนั้นจึงกลายเป็นข้อที่มีตัวเลือกจริงน้อยกว่าที่ตั้งใจ
แก้ด้วยการบีบช่วงค่าตัวแปรให้แคบลง หรือเปลี่ยนสูตรตัวเลือกลวงเป็นความผิดพลาดแบบอื่น

### การแทนค่าใน `stem_tpl`

ระบบแทนเฉพาะ `{ชื่อตัวแปรที่ประกาศใน vars}` เท่านั้น จึงเขียน LaTeX ที่มีวงเล็บปีกกาได้ตามปกติ
เช่น `\\frac{a}{\\sin A}` จะไม่ถูกแตะต้อง

### ชนิดของ `vars[].type`
`"int"` / `"float"` / `"choice"` (ใส่ `"options": [...]` แทน `range`) / `"name"` (สุ่มชื่อคนหรือสิ่งของจาก `options`)

### ฟิลด์เฉลยเป็นของบังคับ
ทุกแม่แบบต้องมี `steps_tpl`, `hints_tpl` และ `explanation_tpl` เพื่อให้โจทย์ที่สุ่มใหม่มีวิธีคิดของตัวเอง ดูรายละเอียดใน **C.7**

### เมื่อทำ template ไม่ได้
บางวิชา parametrize ด้วยตัวเลขไม่ได้ (ภาษาไทย สังคม TGAT3 การอ่านจับใจความ) ให้ใส่:
```json
"template": null,
"template_note": "โจทย์อ่านจับใจความ ไม่สามารถ parametrize ด้วยตัวเลขได้ ต้องแต่งข้อใหม่ทั้งข้อ"
```
วิชาเหล่านี้ให้แต่ง **20 ข้อต่อหัวข้อ** แทนการทำ template

## C.6 `template` แบบ `provider` — เมื่อคำตอบไม่ใช่ตัวเลข หรือโจทย์ต้องมีรูป

`answer_expr` ใน C.4 เป็นนิพจน์เลขคณิต จึงทำได้เฉพาะ **คำตอบที่เป็นตัวเลข** และสร้างรูปไม่ได้
หัวข้ออย่างมิติสัมพันธ์ต้องการสองอย่างที่นิพจน์ให้ไม่ได้
1. คำตอบเป็นชื่อหน้า (ก ข ค) ไม่ใช่ตัวเลข
2. โจทย์ต้องมีรูปที่วาดตามค่าที่สุ่มมา ไม่ใช่รูปเดิมทุกข้อ

**ทางที่ไม่เลือก:** ขยายภาษานิพจน์ให้รองรับข้อความ ลิสต์ และการวาดรูป
เพราะจะกลายเป็นภาษาโปรแกรมย่อยใน JSON ซึ่งตรวจไม่ได้และไม่ปลอดภัย

**ทางที่เลือก:** JSON เรียกได้แค่ **ชื่อฟังก์ชันที่เขียนไว้แล้วใน `scripts/providers/`**
โค้ดอยู่ในไฟล์ที่คนรีวิวได้ JSON ระบุได้แค่ชื่อกับพารามิเตอร์

### รูปแบบ

```json
"template": {
  "provider": "cube_net.opposite_face",
  "answer_kind": "label",
  "params": {
    "nets": ["cross", "cross_c", "tee_col"],
    "orient": true,
    "skip_rule_applies": true,
    "touching_count": 1
  },
  "stem_tpl": "จากแผ่นคลี่ลูกบาศก์ที่กำหนด หน้าใดอยู่ตรงข้ามกับหน้า {asked}\n\n[[fig1]]",
  "quality_rules": [
    "เฉลยต้องมาจากการพับแผ่นคลี่ด้วยโค้ด ไม่ใช่การพับในหัว",
    "ตัวเลือกลวงต้องเป็นหน้าที่ติดกับหน้าที่ถามบนลูกบาศก์ทุกตัว"
  ]
}
```

| ฟิลด์ | บังคับ | ความหมาย |
|---|---|---|
| `provider` | ใช่ | ชื่อ provider ที่มีจริงใน `scripts/providers/` |
| `answer_kind` | ใช่ | `"number"` / `"label"` / `"text"` — ต้องตรงกับที่ provider ประกาศ |
| `params` | ใช่ | พารามิเตอร์ที่ provider นั้นรับ (แต่ละตัวมีรายการของตัวเอง) |
| `stem_tpl` | ใช่ | โจทย์ ใช้ `{ชื่อ}` แทนค่าที่ provider คืนมาได้ |
| `quality_rules` | ควรมี | เงื่อนไขที่ทำให้โจทย์ใช้ได้ (ข้อความสำหรับคนอ่าน) |

### ห้ามใส่ฟิลด์ของโหมดเลขคณิตมาด้วย

`vars` `answer_expr` `display` `constraints` `distractors` `quality_exprs` `answer_round`
**ใส่พร้อม `provider` ไม่ได้** เพราะ provider เป็นคนคำนวณทั้งหมด ฟิลด์พวกนี้จะไม่มีผลอะไร
ซึ่งอันตรายกว่าเขียนผิดตรง ๆ เพราะคนเขียนจะเข้าใจว่าเงื่อนไขถูกบังคับใช้แล้ว —
`validate.py` จึงถือเป็น error

### ถ้าคำตอบไม่ใช่ตัวเลข ตัวโจทย์ต้องสอดคล้องกัน

- `answer_numeric` ต้องเป็น `null`
- ต้องมี `choices` (คำตอบอยู่ใน `choices` เท่านั้น)

### กลุ่ม `shape2d.*` — ใช้เครื่องมือกลางร่วมกัน

สาม provider นี้อยู่ในไฟล์เดียว (`scripts/providers/shape2d_items.py`)
และใช้เครื่องมือกลาง `scripts/shape2d.py` ที่คำนวณการหมุนและการสะท้อนจริง

**เครื่องมือกลางตรวจตัวเองได้** รัน `python scripts/shape2d.py` จะตรวจว่า
หมุนสี่ครั้งกลับมาเท่าเดิม · สะท้อนสองครั้งกลับมาเท่าเดิม ·
รูปที่ใช้ได้มีภาพต่างกัน 8 แบบ · รูปสมมาตรถูกคัดออก

**รูปที่ใช้ต้องไม่สมมาตร** ถ้ารูปสมมาตรในการหมุน ภาพหมุนบางมุมจะเท่ากับรูปเดิม
ทำให้ตัวเลือกซ้ำ และถ้ารูปสะท้อนแล้วเท่ากับภาพหมุนของตัวเอง
จะแยกการหมุนออกจากการสะท้อนไม่ได้เลย ซึ่งเป็นสิ่งที่โจทย์กลุ่มนี้ต้องการวัด

### `paper_fold.punch_pattern` — provider ตัวแรกที่ตัวเลือกเป็นรูป

โจทย์แบบนี้ผู้สอบต้องเลือก **รูป** ไม่ใช่ข้อความ provider จึงคืนเพิ่ม
`answer_fig` และ `fig` ในตัวลวงแต่ละตัว แล้ว `choices[].md` เป็น `[[figN]]`
โดยมีรูปครบทุกตัวใน `figures` (1 รูปโจทย์ + 5 รูปตัวเลือก = 6 รูปต่อข้อ)

`value` ของตัวเลือกยังเป็นข้อความพิกัดรูแบบมาตรฐาน ไม่ใช่ชื่อรูป
เพราะเกณฑ์คุณภาพใช้ค่านี้ตรวจว่าตัวเลือกซ้ำกันไหม

**validator ตรวจให้ว่าการอ้าง `[[figN]]` ในโจทย์ชี้ไปหารูปที่มีจริง**
(ตรวจทั้ง `stem_md`, `choices[].md`, `solution_steps`, `hints`, `distractor_reasons`)
ถ้ารูปหาย ผู้สอบจะเห็นตัวเลือกว่างเปล่าแล้วเดาไม่ได้เลย

พารามิเตอร์ของ `cube_net.*` คุม **โครงของโจทย์** ไม่ใช่หน้าตา จึงใช้ล็อกความยากได้
- `nets` กลุ่มแผ่นคลี่ (แบ่งตามจำนวนคู่ที่กฎเว้นหนึ่งช่องหาได้ 3/3, 2/3, 1/3, 0/3)
- `skip_rule_applies` กฎเว้นหนึ่งช่องใช้กับคู่นี้ได้หรือไม่
- `touching_count` ตัดตัวเลือกได้กี่ตัวในขั้นแรก (4 = จบขั้นเดียว, 1 = ต้องใช้กฎอื่นต่อ)
- `orient` สุ่มการหมุน/พลิกแผ่นคลี่ แล้วใส่ตัวอักษรใหม่ตามลำดับการอ่าน
  ได้โจทย์ที่ต่างกันในสายตาผู้สอบแต่รูปทรงเดิม **ความยากจึงเท่าเดิม**

ตั้ง 3 ตัวแรกให้ตรงกับข้อที่เขียนไว้ แล้วโจทย์ที่สุ่มใหม่จะมีวิธีคิดจำนวนขั้นเท่ากันเสมอ

### สัญญาที่ provider ต้องทำตาม

อ่านรายละเอียดใน `scripts/providers/__init__.py` โดยสรุป
- คืนตัวเลือกลวงที่ **มีเหตุผลกำกับทุกตัว** เหมือนแม่แบบปกติ (เกณฑ์ตรวจคุณภาพใช้ชุดเดียวกัน)
- ต้องให้ผลเหมือนเดิมทุกครั้งเมื่อรับค่าเดิม ห้ามอ่านไฟล์ ห้ามต่อเน็ต ห้ามใช้เวลาปัจจุบัน
  ไม่อย่างนั้นการตรวจชั้นที่ 2 จะให้ผลไม่ซ้ำเดิมและเลิกเชื่อถือได้

### การเขียน provider ใหม่ถือเป็นการแก้โค้ด ไม่ใช่การเพิ่มข้อมูล

ต้องรัน `selftest.py` ให้ผ่านทุกครั้ง และเพิ่มเคสข้อผิดพลาดของ provider ใหม่เข้าไปด้วย

## C.7 เฉลยของโจทย์ที่สุ่มใหม่ — `steps_tpl` / `hints_tpl` / `explanation_tpl`

### ปัญหาที่ส่วนนี้แก้

`solution_steps` `hints` `answer_explanation_md` ในข้อ C.2 เป็นเฉลยของ **ข้อต้นฉบับข้อเดียว**
ถ้ามีแค่นั้น เวลาผู้ใช้กดสุ่มโจทย์ใหม่จะได้โจทย์ที่ตัวเลขเปลี่ยนไปแล้ว
แต่เฉลยยังเป็นตัวเลขชุดเดิม — ซึ่งผิดและสร้างความสับสนมากกว่าไม่มีเฉลยเลย

เว็บนี้มีฟีเจอร์ A ไว้ให้คนเรียนจาก 0 โจทย์ที่มีแต่คำตอบไม่มีวิธีคิดจึงใช้ไม่ได้
**แม่แบบทุกอันต้องอธิบายตัวเองได้** — เป็นฟิลด์บังคับ ไม่ใช่ของแถม

### รูปแบบ

```json
"steps_tpl": [
  {
    "do_md": "เขียนผลต่างทุกช่วง: ${t2}-{a1}={d}$, ${t3}-{t2}={d}$",
    "why_md": "ยืนยันว่าผลต่างคงที่จริงก่อนสรุป ไม่ใช่ดูจากช่วงเดียว"
  },
  {
    "do_md": "$d={d}$ บวกต่อหนึ่งครั้ง: ${t4}+{d}={answer}$",
    "why_md": "ถามพจน์ถัดไปพจน์เดียว การบวกตรง ๆ เร็วกว่าแทนสูตร"
  }
],
"hints_tpl": [
  "ขั้นแรกให้เขียนผลต่างระหว่างพจน์ที่ติดกันลงไป",
  "ผลต่างเท่ากันทุกช่วง แปลว่าเป็นอนุกรมผลต่างคงที่",
  "ผลต่างคือ ${d}$ เริ่มจาก ${t4}+{d}$"
],
"explanation_tpl": "ตอบ ${answer}$ อนุกรมนี้เพิ่มขึ้น ${d}$ ทุกพจน์"
```

| ฟิลด์ | บังคับ | กฎ |
|---|---|---|
| `steps_tpl` | ใช่ | อาร์เรย์ อย่างน้อย **2 ขั้น** ทุกขั้นมี `do_md` และ `why_md` ที่ไม่ว่าง |
| `hints_tpl` | ใช่ | **3 ระดับเสมอ** ไม่มีข้อว่าง |
| `explanation_tpl` | ใช่ | ข้อความเดียว ไม่ว่าง |

### แทนค่าได้เหมือน `stem_tpl` บวกชื่อพิเศษ `answer`

ใช้ `{ชื่อ}` ของ `vars` และ `display` ได้ทั้งหมด และใช้ `{answer}` ได้ด้วย
โดย `{answer}` จะถูกจัดรูปแบบเดียวกับที่แสดงในตัวเลือก (ถ้า `answer_round` เป็น 1 จะได้ `18.0` ไม่ใช่ `18`)

ถ้าเฉลยต้องอ้างค่ากลางทาง ให้ประกาศเพิ่มใน `display` ไม่ใช่เขียนเลขตายตัว เช่น
```json
"display": {
  "nm1": "n - 1",
  "prod": "(n - 1)*d"
}
```
แล้วเขียน `"คำนวณ ${nm1} \\times {d}={prod}$"`

### วงเล็บปีกกาของ LaTeX ไม่ถูกแตะ

ตัวแทนค่าจะข้ามปีกกาที่ต่อท้ายคำสั่ง LaTeX หรือต่อท้ายปีกกาอีกอัน
จึงเขียนสูตรปนกับช่องแทนค่าได้ตามปกติ

| เขียน | ได้ |
|---|---|
| `$a_{{n}}$` | `$a_{20}$` (ช่องแทนค่าในตัวห้อย) |
| `$\dfrac{{ak}-{a1}}{{km1}}$` | `$\dfrac{400-250}{3}$` |
| `$\frac{a}{\sin A}$` | ไม่เปลี่ยน (ไม่มีชื่อตัวแปรอยู่ในปีกกา) |
| `$\sqrt{x}$` | ไม่เปลี่ยน แม้ `x` จะไม่ได้ประกาศ |

### กฎเหล็ก: คำใบ้ห้ามบอกคำตอบ

`render_template.py --stress` จะแทนค่าจริงหลายร้อยรอบแล้วเช็คว่า
**ไม่มีคำใบ้ข้อใดมีค่าคำตอบอยู่ในข้อความ** ถ้ามีถือเป็น error
เพราะไม่อย่างนั้นการกดขอคำใบ้จะกลายเป็นการกดดูเฉลย

จุดที่พลาดง่ายคือ **ค่าอื่นในคำใบ้ไปตรงกับคำตอบโดยบังเอิญ**
เช่นข้อที่ตอบ `k+1` แต่คำใบ้พิมพ์ `a1` ออกมา — ถ้าสุ่มได้ `a1 = k+1` ก็กลายเป็นเฉลย
**แก้ที่ `constraints`** เช่นเพิ่ม `"a1 != k + 1"` ไม่ใช่ลบตัวเลขออกจากคำใบ้
เพราะตัวเลขในคำใบ้คือสิ่งที่ทำให้คำใบ้มีประโยชน์

การเทียบใช้ขอบเขตคำ ไม่ใช่การค้นข้อความตรง ๆ
เลข `7` จึงไม่ถูกนับว่าโผล่ใน `17` และชื่อหน้า `ก` ไม่ถูกนับว่าโผล่ในคำว่า `จาก`

### แม่แบบแบบ `provider` ทำเรื่องนี้ด้วยโค้ด

provider ต้องคืน `steps` `hints` `explanation` มาพร้อมคำตอบ (ดู C.6)
และต้องสร้างจากค่าที่สุ่มมาจริง เช่นในตัวพับกล่อง ขั้นตอนจะเปลี่ยนไป
ตามว่ากฎเว้นหนึ่งช่องใช้กับคู่ที่สุ่มได้หรือไม่ ไม่ใช่ข้อความสำเร็จรูปชุดเดียว

### ดูผลก่อนส่งให้คนตรวจ

```
python scripts/render_template.py --show <topic_id> --full
```
แสดงโจทย์ที่สุ่มได้พร้อมวิธีคิด คำใบ้ และคำอธิบายคำตอบ

## C.8 `mcq4_tiered` — ข้อสอบที่ให้คะแนนลดหลั่น (ข้อสอบสถานการณ์)

### ปัญหาที่ส่วนนี้แก้

`mcq4` และ `mcq5` ถือว่าตัวเลือกมีแค่ถูกกับผิด ซึ่งใช้ไม่ได้กับข้อสอบสถานการณ์
อย่าง **TGAT3** ที่ผังสอบระบุชัดว่าให้คะแนน **แบบลดหลั่น 0.25 ถึง 1.00**

ในข้อสอบแบบนี้ ตัวเลือกหลายตัวเป็นคำตอบที่ยอมรับได้ ต่างกันที่ดีกว่าหรือด้อยกว่า
เช่น "รีบลงมือแก้เอง" อาจได้ 0.5 ส่วน "แจ้งหัวหน้าก่อนแล้วลงมือ" ได้ 1.00

**ถ้าทำเป็นถูก/ผิดจะสอนผิดไปเลย** เพราะสิ่งที่ผู้เรียนต้องได้คือ
เกณฑ์ว่าอะไรดีกว่าอะไร ไม่ใช่การจำว่าข้อไหนถูก

### รูปแบบ

```json
{
  "format": "mcq4_tiered",
  "choices": [
    {"md": "แจ้งหัวหน้าก่อน แล้วลงมือแก้ตามที่ตกลง", "is_answer": true,  "score": 1},
    {"md": "ลงมือแก้เองทันทีแล้วค่อยรายงานภายหลัง",   "is_answer": false, "score": 0.5},
    {"md": "รอให้หัวหน้าสั่งก่อนจึงทำอะไร",            "is_answer": false, "score": 0.25},
    {"md": "ปล่อยไว้เพราะไม่ใช่หน้าที่ของเรา",          "is_answer": false, "score": 0}
  ]
}
```

### กฎ (validator ตรวจให้)

| กฎ | เหตุผล |
|---|---|
| ต้องมี 4 ตัวเลือกพอดี | ตามผังสอบ TGAT3 |
| ทุกตัวเลือกต้องมี `score` | ถ้าขาดแม้ตัวเดียวแปลว่ายังคิดไม่ครบ |
| `score` ใช้ได้เฉพาะ 0, 0.25, 0.5, 0.75, 1 | ผังสอบใช้ขั้นละ 0.25 ห้ามตั้งขั้นเอง |
| ต้องมีตัวที่ได้ 1 คะแนน **ตัวเดียว** | ต้องมีคำตอบที่ดีที่สุดชัดเจน |
| ตัวที่ได้ 1 คะแนนต้องเป็นตัวที่ `is_answer: true` | สองฟิลด์นี้ต้องตรงกันเสมอ |
| ห้ามตั้ง `is_answer: true` ให้ตัวที่ score ไม่ใช่ 1 | กันความสับสนในหน้าเว็บ |

**คำเตือน (ไม่ใช่ error)**
- ถ้าไม่มีตัวเลือกที่ได้คะแนนบางส่วนเลย → ใช้ `mcq4` ธรรมดาดีกว่า
- ถ้าทุกตัวเลือกได้คะแนน → ข้อนั้นแยกคนเก่งกับคนเดาไม่ออก

### `distractor_reasons` เปลี่ยนความหมาย

ในข้อแบบลดหลั่น คำว่า "ตัวลวง" ไม่ตรงความจริง ตัวเลือกที่ได้ 0.5 ไม่ใช่ตัวลวง
แต่เป็นคำตอบที่ใช้ได้ระดับหนึ่ง จึงต้องเขียน `distractor_reasons` ให้ตรงกับคะแนน

- ตัวที่ได้ **0** → อธิบายว่าทำไมใช้ไม่ได้
- ตัวที่ได้ **0.25-0.75** → อธิบายว่า **ดีตรงไหน และขาดอะไรจึงไม่ใช่ตัวที่ดีที่สุด**

ข้อที่เขียนเหตุผลว่า "ผิดเพราะไม่ใช่คำตอบ" ให้กับตัวเลือกที่ได้ 0.5
ถือว่าเขียนไม่ผ่าน แม้ validator จะจับไม่ได้ก็ตาม

### `solution_steps` ต้องเป็นเกณฑ์ ไม่ใช่การคำนวณ

เขียนให้ผู้เรียนได้ **เกณฑ์ที่เอาไปใช้กับข้ออื่นได้** เช่น
"แก้ที่ต้นเหตุดีกว่าแก้อาการ" หรือ "อยู่ในอำนาจหน้าที่เราไหม"
ห้ามเขียนว่า "ข้อนี้ถูกเพราะเป็นคำตอบที่ถูก"

### สิ่งที่สเปคนี้ยังรองรับไม่ได้

ผังสอบ TGAT3 ระบุรูปแบบข้อสอบไว้ 3 แบบ สเปคนี้รองรับ 2 แบบ

| รูปแบบตามผังสอบ | สถานะ |
|---|---|
| เลือกตอบตัวเดียว ให้คะแนนลดหลั่น | ใช้ `mcq4_tiered` ได้ |
| เลือกได้หลายข้อ ตัวเลือกละ 0.25 คะแนน | ใช้ `multi_select` ได้ แต่ยังไม่มีฟิลด์เก็บคะแนนต่อตัวเลือก |
| **ข้อสอบ 2 ข้อที่สัมพันธ์กัน คะแนนผูกกัน รวม 2 คะแนน** | **ยังรองรับไม่ได้** |

แบบที่สามต้องมีฟิลด์เชื่อมสองข้อเข้าด้วยกัน ซึ่งยังไม่ได้ออกแบบ
**อย่าแต่งข้อแบบนี้จนกว่าจะเพิ่มฟิลด์** ถ้าแต่งไปจะเก็บความสัมพันธ์ของคะแนนไม่ได้
