# เกณฑ์ตรวจงานตัวเองก่อนส่ง — ใช้กับทุกใบสั่งงาน

> ใบสั่งงานถาวร ไม่มีเลขรอบ **ทุกครั้งที่ทำงานเสร็จ ให้ทำตามไฟล์นี้ก่อนบอกว่าเสร็จ**
> และใส่หัวข้อ "ผลตรวจตัวเอง" ท้ายรายงานของรอบนั้นตามแบบในข้อ 6
> ถ้าใบสั่งงานรายรอบขัดกับไฟล์นี้ ให้ถือใบสั่งงานรายรอบ

## ทำไมต้องมี

ทุกเกณฑ์ในไฟล์นี้มาจากข้อผิดที่เกิดจริงในรอบ 7–12 ทั้งของคุณและของ Claude
ตัวตรวจอัตโนมัติ (`validate.py` และ `--stress`) จับได้แค่รูปแบบ ข้อผิดที่หลุดไปถึงผู้ตรวจอีกฝ่ายเกือบทั้งหมดเป็นเรื่อง **ความหมาย**
การตรวจตัวเองจึงต้องทำด้วยการอ่านและคิด ไม่ใช่แค่รันคำสั่งให้ผ่าน

วิธีคิดหลัก: **เปลี่ยนบทบาทเป็นผู้ตรวจที่พยายามหักล้างงานตัวเอง** แบบเดียวกับที่คุณทำกับงานของ Claude ในรอบ 11 และ 12

## 1. ทุกข้อที่เขียนใหม่หรือแก้ — ตรวจด้วยการทำข้อนั้นเอง

ทำทีละข้อ โดย **ปิดเฉลยก่อน**

| # | เกณฑ์ | วิธีตรวจ | ข้อผิดจริงที่เป็นที่มา |
|---|---|---|---|
| 1.1 | คำตอบถูก | อ่านโจทย์แล้วทำเองจากศูนย์ ได้คำตอบแล้วจึงเปิดเฉลยเทียบ | เฉลยทำเครื่องหมายผิดข้อ (รอบแรก ๆ) |
| 1.2 | มีคำตอบเดียว | **พยายามปกป้องตัวลวงทีละตัว** ถามว่า "มีการตีความใดที่ทำให้ตัวนี้ถูกไหม" ถ้าหาได้แม้การตีความเดียว ต้องแก้ | รอบ 10: ตัวลวงใหม่ 3 ตัวเป็นคำตอบถูกได้ · รอบ 11: พื้นที่หน้าตัด 20% กับ 44% · กฎอุปมาอุปไมย 6 ข้อ |
| 1.3 | ตัวลวงทุกตัวผิดเพราะ **ข้อเท็จจริงที่ระบุได้** | เหตุผลของตัวลวงต้องตอบได้ว่าผิดข้อใด ไม่ใช่ "ไม่ตรง" หรือ "ผิดกฎ" | รอบ 11: ตัวลวงวัคซีนที่เป็นจริง |
| 1.4 | ตัวเลขของตัวลวงได้จากวิธีผิดที่เขียนไว้จริง | คำนวณตามวิธีผิดในเหตุผล แล้วดูว่าได้ค่าของตัวลวงนั้น | รอบ 11: 12.56 กับ 5.02 m³ · 400,000 Pa · รอบ 12: pitfall เฟืองที่ได้ 1 ซึ่งถูก |
| 1.5 | โจทย์ให้ข้อมูลครบและไม่กำกวม | อ่านเฉพาะโจทย์ ถามว่ามีคำใดตีความได้สองแบบ (เช่น "ไม่ชอบทั้งสองอย่าง" "จากชั้นล่างถึงชั้น 18") | รอบ 12: venn · รอบ 11: สายเคเบิล 17 หรือ 18 ชั้น |
| 1.6 | กฎต้องมีแบบเดียว (ข้ออนุกรม อุปมาอุปไมย หาตัวต่าง) | หากฎคู่แข่งที่อธิบายข้อมูลที่ให้ครบ ถ้าให้คำตอบต่างกันและคำตอบนั้นอยู่ในตัวเลือก ต้องแก้ | รอบ 11: บวก 2 กับ คูณ 3 · หมุนกับสะท้อน |
| 1.7 | คำอธิบายเฉลยบอกเหตุผล | ต้องเป็นรูป "ตอบ … เพราะ …" ไม่ใช่ทวนคำตอบ | รอบ 12: 67 ข้อ |

## 6. รายงาน — เขียนก่อนบอกว่าเสร็จ และต้องมีหัวข้อนี้ท้ายไฟล์

```markdown
## ผลตรวจตัวเอง

| เกณฑ์ | ตรวจแล้ว | ผล / ตัวเลข |
|---|---|---|
| 1.1–1.7 ทำข้อเองทุกข้อที่แก้ | N จาก N ข้อ | พบและแก้เอง K ข้อ: (id และสิ่งที่พบ) |
| 1.2 พยายามปกป้องตัวลวงทุกตัว | N ตัว | ตัวที่ปกป้องได้และแก้แล้ว: … |
| 1.4 คำนวณตามวิธีผิดของตัวลวง | N ตัว | ไม่ตรง K ตัว แก้แล้ว |
| 2.1–2.5 รูปแบบเดาคำตอบ | ทุกหัวข้อที่แตะ | ตัวเลขต่อหัวข้อ |
| 3.1–3.6 บทเรียน | N บท หรือ "ไม่เกี่ยว" | … |
| 4.1–4.3 รูป | N รูป หรือ "ไม่เกี่ยว" | … |
| 5.1–5.7 เทคนิคและขอบเขต | ครบ | ผลคำสั่งแต่ละตัว |

### สิ่งที่ยังไม่ได้ทำ หรือไม่แน่ใจ
- (เขียนตรง ๆ ถ้าไม่มีให้เขียนว่า "ไม่มี")
```

กติกาของตารางนี้

- **ช่อง "พบและแก้เอง" ที่เป็นศูนย์ทุกแถวไม่ใช่ผลที่ดี** ถ้าตรวจจริงมักเจออย่างน้อยหนึ่งจุด รอบ 11 คุณเจอ 4 จุดในงานตัวเอง (400,000 Pa และอีกสามข้อ) นั่นคือการตรวจที่ได้ผล
- เกณฑ์ใดไม่เกี่ยวกับงานรอบนั้น เขียนว่า "ไม่เกี่ยว" พร้อมเหตุผลสั้น ๆ อย่าเว้นว่าง
- ถ้าทำไม่ครบขอบเขต บอกว่าทำถึงไหน **อย่าเขียนว่าเสร็จ**
- ตัวเลขทุกตัวในรายงานต้องมาจากการนับจริงด้วยสคริปต์หรือ `git diff` ไม่ใช่ประมาณ
- ถ้าไม่เห็นด้วยกับเกณฑ์ข้อใดในงานนั้น เขียนเหตุผลได้ Claude จะพิจารณา

## 7. ลำดับที่แนะนำ

1. ทำงานตามใบสั่งงาน
2. build + validate + stress ให้ผ่าน (ข้อ 5)
3. **พักจากงานนั้น แล้วกลับมาอ่านทุกข้อที่แก้ใหม่ในฐานะผู้ตรวจ** (ข้อ 1–4) ใช้ไฟล์ JSON ที่ build แล้ว ไม่ใช่ต้นฉบับที่เพิ่งเขียน
4. แก้สิ่งที่เจอ แล้วกลับไปข้อ 2
5. เขียนรายงานพร้อมตาราง "ผลตรวจตัวเอง"
6. บอกว่าเสร็จ
